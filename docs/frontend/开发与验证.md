# Web 开发与验证

需要 Node.js 24+、可用 Docker/Podman 和已有 `postgres:17-alpine` 镜像。

```bash
npm ci
# 终端 1
task run:test-server
# 终端 2
task run:web
```

打开 `http://127.0.0.1:5173`。Vite 固定 5173 端口，将 `/api` 和 `/auth`
代理到 `http://127.0.0.1:8080`，保留浏览器 Origin 供后端校验。不要改用
localhost 访问；地址或端口变更时应同步修改 Vite 和 `PALACE_ORIGIN`。
生产 OIDC 的 Secure cookie 需要 HTTPS，同源部署时才走完整登录流程。

`task build:frontend` 生成 `apps/palace-web/dist`。开发环境由 Vite 提供页面；生产 server 托管该目录，`/api/*`、`/auth/*` 保持各自路由，其他前端页面
（含 `/?date=…` 与 `/conversations/:id` 深链接）以 200 回退到 `index.html`。缓存策略见[组件与样式](组件与样式.md#http-缓存)。

`task run:test-server` 会对 `.data/postgres` 中的本地数据执行全部迁移；涉及删除列的迁移（如 `0010_path_titles.sql`）不可回退，需要保留旧数据时先备份。

完整配置见[服务端环境变量](../server/环境变量.md)。

## 验证

- `task test`：前端与 Rust lint、默认测试、API 生成漂移与契约检查。
- `task test:frontend`：类型化客户端与组件交互测试，stderr 必须为空。
- `task test:integration`：真实 PostgreSQL 与 HTTP 契约测试。
- `task test:browser`：真实 Chromium 验证桌面/手机交互与浏览器编码，使用受控 HTTP 响应，不代替数据库测试。
- `task build:frontend`：构建前端；组件 registry 的构建见[组件与样式](组件与样式.md)。

浏览器测试需先执行 `npm exec playwright install chromium`。
默认使用 5173 端口，也可通过 `PALACE_BROWSER_TEST_PORT=5174 task test:browser` 使用独立端口。
当前对话功能的回归范围见[分支与路径](../features/conversations/分支与路径.md#验证)。
