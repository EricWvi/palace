# Web 组件与样式

本文路径以 `apps/palace-web/` 为基准。

- `src/components/ui` 是从 shadcn registry 获取并本地修改的源代码；Radix 负责弹层交互。
- `src/theme.css` 定义 Palace 配色和 token；`src/styles.css` 定义页面布局，支持手机宽度。
- React Day Picker 提供日期选择能力；具体发生时间和默认值由业务功能决定。

## 迁移到原型设计风格

> 迁移方案，尚未实施。完成后用本节替换上面关于 `theme.css` 的说明。

Web 端的视觉以 [`docs/design`](../design/README.md) 下的原型为准。页面结构与交互见
`specs/decisions/web/navigation/` 等 ADR，本节只约定样式体系。

### token 只有一份

- `src/styles.css` 直接导入 `../../../docs/design/tokens.css`，不复制、不生成副本。修改颜色、字体、字号或圆角只改这一个文件，原型和应用同时生效。
- `src/theme.css` 不再定义颜色值，只保留 Tailwind `@theme inline` 映射，把 shadcn 使用的变量指向 token，例如 `--color-background: var(--bg)`、`--color-primary: var(--accent)`、`--color-border: var(--border)`。
- 组件只引用按用途分的字体 token（`--font-display`、`--font-ui`、`--font-content`），不写具体字体名。宋体只用于展示性的大字，18px 以下的中文控件文字用 `--font-ui`。
- 深色模式随 token 一起生效：跟随系统偏好，也可以用 `data-theme` 固定。原来“只支持浅色”的限制随之取消。
- Docker 的前端构建阶段要额外复制 `docs/design/tokens.css`，否则构建时找不到被导入的文件。Vite 开发服务器默认允许访问 workspace 根目录，不需要改 `server.fs.allow`。
- `docs/design/tokens.css` 从此是线上样式的一部分，改动它要像改应用代码一样检查应用页面。

`registry.json` 中的 `palace-style` 同样指向这份 token，不再打包 `theme.css` 里的颜色副本。

### shadcn 组件按原型风格改造

组件源码仍在 `src/components/ui`，按以下原则修改，不新增第二套组件：

| 组件 | 原型风格 |
| --- | --- |
| Button | 默认是文字按钮：无底色、无边框，悬停时颜色加深或出现下划线；只有对话框中的主操作使用 accent 底色按钮 |
| Dialog | `--surface-raised` 背景、`--border` 描边、`--radius-md` 圆角，阴影很淡；标题用展示字体，正文用 `--font-ui` |
| Popover、菜单 | 与原型中 `···` 菜单一致：文字菜单项，悬停时 `--bg-sunken` 底色，破坏性操作排最后 |
| Input、Select | `--bg-sunken` 底色、`--border` 描边，聚焦时描边变为 `--accent` |
| Calendar | 颜色全部来自 token，选中日用 accent，今天用文字强调而不是底色块 |

图标尽量删去：导航、类型标记、来源、操作都用文字表达。只在文字无法替代时保留 lucide 图标，颜色用 `--text-3`。

### EB Garamond 自己托管

- 用 npm 依赖 `@fontsource/eb-garamond`（锁定版本）提供字体文件，只导入原型用到的字重：400、500 和 400 斜体，子集为 `latin` 与 `latin-ext`。
- 字体经 Vite 打包到 `dist/assets/`，文件名带内容哈希；`font-display: swap`，字体加载前先用后备字体显示文字。
- 中文宋体不托管：体积太大，使用系统字体（macOS 的 Songti SC、Linux 的 Noto Serif CJK SC），与 token 中的字体列表一致。
- 原型页面仍从 Google Fonts 加载 EB Garamond，它们只在本地打开，不受此约束。

### HTTP 缓存

生产环境由 `palace-server` 托管 `dist`（`apps/palace-server/src/server.rs` 中的 `ServeDir`），需要按文件是否带哈希设置 `Cache-Control`：

| 路径 | `Cache-Control` | 原因 |
| --- | --- | --- |
| `/assets/*`（JS、CSS、字体等带哈希的文件） | `public, max-age=31536000, immutable` | 内容变化时文件名随之变化，旧文件可以永久缓存 |
| `index.html` 及前端路由回退 | `no-cache` | 每次都要向服务端确认，才能在发布后拿到新的资源文件名 |
| 其他 `public/` 文件（如 `/r/*`） | `no-cache` | 文件名不带哈希，依靠 `ServeDir` 提供的 `Last-Modified` 做条件请求 |

`/api/*` 与 `/auth/*` 的缓存策略不变。验证时检查字体请求在第二次加载时直接命中浏览器缓存，`index.html` 每次都发出条件请求。

## 自有 shadcn style

`registry.json` 中的 `palace-style` 使用 `type: "registry:style"` 与
`extends: "none"`，打包本地组件、CSS 文件、CSS variables 和依赖。
这符合 [shadcn 自定义 style 文档](https://ui.shadcn.com/docs/registry/examples)。
`components.json` 的 `style: "new-york"` 只是 CLI 获取官方起始组件的配置，
不是 Palace registry 的继承关系；应用实际视觉由本地源码与 token 决定。

```bash
npm run registry:build -w apps/palace-web
```

构建结果在 `public/r`，运行 Vite 后可访问 `/r/palace-style.json`。
其他 Tailwind v4 项目可通过 `npx shadcn add http://127.0.0.1:5173/r/palace-style.json`
安装，并在主 CSS 的 Tailwind import 之后导入生成的 `src/theme.css`。
该 registry 面向 light mode，目前不定义 dark theme。
