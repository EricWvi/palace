# Web 组件与样式

本文路径以 `apps/palace-web/` 为基准。Web 端的视觉以 [`design`](../../design/README.md) 下的原型为准；
页面结构与交互见 `specs/decisions/web/navigation/` 等 ADR，本文只约定样式体系。

- `src/styles.css` 依次导入 Tailwind、`../../../design/tokens.css` 和 `src/theme.css`，再写页面样式。
  页面样式按原型移植：`base.css`、`components.css`，以及 `1-prototype.html`（时刻）和
  `2.1-moment-conversation.html`（摘星阅读页）中的页面样式。
- `src/components/ui` 是从 shadcn registry 获取并本地修改的源代码；Radix 负责弹层和菜单交互。
- React Day Picker 提供导入表单中的日期选择；时刻页的日期标题使用浏览器原生日期选择器，与原型一致。

## token 只有一份

- `design/tokens.css` 是唯一的颜色、字体、字号和圆角来源，原型和应用同时生效，不复制、不生成副本。
  它是线上样式的一部分，改动它要像改应用代码一样检查应用页面。
- `src/theme.css` 只有 Tailwind `@theme inline` 映射，把 shadcn 使用的名字指向 token，例如
  `--color-background: var(--bg)`、`--color-primary: var(--accent)`。shadcn 的 `accent` 指悬停底色，映射到
  `--bg-sunken`，与 Palace 的 `--accent` 颜色不是一回事。
- token 不分层导入，Tailwind 的主题变量在 `theme` 层，因此同名变量（如 `--font-sans`、`--radius-md`）以 token 为准。
- 页面的元素级默认样式（`body`、`:focus-visible` 等）放在 `@layer base`，组件上的 Tailwind 类才能覆盖它们；
  页面专属的类名样式不分层。
- 组件只引用按用途分的字体 token（`--font-display`、`--font-ui`、`--font-content`），不写具体字体名。
  展示字体只用于大字和时间线卡片，18px 以下的中文控件文字用 `--font-ui`。
- 深色模式随 token 生效：跟随系统偏好，也可以用 `data-theme` 固定。
- Docker 的前端构建阶段额外复制 `design/tokens.css`、`design/ornament.js` 和 `design/ornament.d.ts`。Vite 默认允许访问 workspace 根目录，不需要改 `server.fs.allow`。

## 装饰 SVG 只有一份

`design/ornament.js` 通过 `globalThis.palaceOrnament` 提供只读的路径与 viewBox，
`design/ornament.d.ts` 提供 TypeScript 类型。`src/components/ornament.tsx` 副作用导入该脚本后
渲染内联 SVG；原型用普通 `<script>` 在 `shared.js` 之前加载同一文件，仍可直接通过 `file://` 打开。
修改装饰只更新 `design/ornament.js`，两端保持 `currentColor` 和 `--ornament` 控制颜色。

## 组件按原型风格改造

组件源码仍在 `src/components/ui`，不新增第二套组件：

| 组件 | 原型风格 |
| --- | --- |
| Button | `ghost`、`link` 是文字按钮：无底色、无边框，悬停时出现浅底色或下划线；只有对话框中的主操作用 accent 底色的 `default` |
| Dialog | `--surface-raised` 背景、`--border` 描边、`--radius-md` 圆角，阴影很淡；标题用展示字体 |
| 菜单 | `MoreMenu`（`src/components/more-menu.tsx`）：`···` 在所属区域悬停时出现，聚焦、展开或触屏时保持可见；文字菜单项，破坏性操作排最后 |
| Input、Select | `--bg-sunken` 底色、`--border` 描边，聚焦时描边变为 `--accent` |
| Calendar | 颜色全部来自 token，选中日用 accent 底色，今天只用 accent 文字 |

`MoreMenu` 的悬停区域由父元素的 `reveals-more` 类决定。图标尽量删去：导航、类型、来源和操作都用文字表达；
目前只保留对话框关闭按钮和日历翻页的 lucide 图标。

## EB Garamond 自己托管

- 用锁定版本的 `@fontsource/eb-garamond` 提供字体文件，`src/main.tsx` 只导入 400、500 和 400 斜体三个文件。
  每个文件为各字符子集声明 `unicode-range`，浏览器只下载页面用到的子集（中文页面通常只有 latin）。
- 字体经 Vite 打包到 `dist/assets/`，文件名带内容哈希；`font-display: swap`，字体加载前先用后备字体显示文字。
- 中文宋体不托管：体积太大，使用系统字体（macOS 的 Songti SC、Linux 的 Noto Serif CJK SC），与 token 中的字体列表一致。
- 原型页面仍从 Google Fonts 加载 EB Garamond，它们只在本地打开。

## HTTP 缓存

生产环境由 `palace-server` 托管 `dist`（`apps/palace-server/src/web_app.rs`），按文件是否带哈希设置 `Cache-Control`：

| 路径 | `Cache-Control` | 原因 |
| --- | --- | --- |
| `/assets/*` 找到的文件 | `public, max-age=31536000, immutable` | 内容变化时文件名随之变化，旧文件可以永久缓存 |
| `/assets/*` 找不到的文件 | 不设置，返回 404 | 不能把 `index.html` 以这个名字缓存一年 |
| `index.html` 及前端路由回退 | `no-cache` | 每次都向服务端确认，发布后才能拿到新的资源文件名 |
| 其他 `public/` 文件（如 `/r/*`） | `no-cache` | 文件名不带哈希，依靠 `Last-Modified` 做条件请求 |

`/api/*` 与 `/auth/*` 的缓存策略不变（业务响应 `no-store`）。

## 自有 shadcn style

`registry.json` 中的 `palace-style` 使用 `type: "registry:style"` 与 `extends: "none"`，打包本地组件、
`design/tokens.css`（安装为 `src/tokens.css`）和 `src/theme.css`，不再打包颜色副本。
这符合 [shadcn 自定义 style 文档](https://ui.shadcn.com/docs/registry/examples)。
`components.json` 的 `style: "new-york"` 只是 CLI 获取官方起始组件的配置，不是 Palace registry 的继承关系。

```bash
npm run registry:build -w apps/palace-web
```

构建结果在 `public/r`，运行 Vite 后可访问 `/r/palace-style.json`。其他 Tailwind v4 项目可通过
`npx shadcn add http://127.0.0.1:5173/r/palace-style.json` 安装，并在主 CSS 的 Tailwind import 之后依次导入
`src/tokens.css` 和 `src/theme.css`。
