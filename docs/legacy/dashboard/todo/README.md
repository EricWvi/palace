# Todo：收集、规划与执行

[返回总览](../../README.md) · [截图](../../screenshots/Todo.png) · [数据库总览](../../data/README.md)

Todo 保存可以长期存在、反复安排到某一天执行的事项。首页 Today 是这些事项的日期视图，Todo 页是集合和事项的管理入口。

## 页面结构与数据

桌面左侧是集合导航，右侧为活动事项，展开归档后出现额外区域。移动端用集合下拉菜单切换，归档显示在列表下方。初始选中 Inbox。事项展示标题、难度色条、日期徽标、草稿 / 看板入口及外部链接；复杂操作位于右键 / 触摸上下文菜单。

| 表             | 本页用途                                   |
| -------------- | ------------------------------------------ |
| `d_collection` | 用户创建的集合名称，按创建时间排列         |
| `d_todo`       | 事项属性、归属、排序、日期、执行与归档状态 |
| `d_tiptap`     | `draft` 指向正文，`kanban` 指向看板 JSON   |
| `d_media`      | 正文内的上传附件                           |

Inbox 是前端补入的 ID 0 集合，数据库只通过 `d_todo.collection_id=0` 表示归属；它不是 `d_collection` 的普通记录。

## 两种完成与三个层级

| 操作 / 对象     | 语义                                     | 不应误解为                   |
| --------------- | ---------------------------------------- | ---------------------------- |
| Done / 完成     | 今天执行过一次，`done=true`，`d_count+1` | 永久完成事项                 |
| Undone / 撤销   | 撤销这次执行，`done=false`，`d_count-1`  | 从归档恢复                   |
| Complete / 归档 | `completed=true`，退出活动事项与 Today   | 删除记录                     |
| Restore / 恢复  | `completed=false`，回到原集合顶部        | 创建新事项或撤销历史执行计数 |
| 集合            | 组织多个 Todo                            | 看板列                       |
| Todo            | 可有计划、链接、正文和看板的长期事项     | 看板内部的单张卡片           |
| 看板卡片        | 某个 Todo 工作材料中的局部步骤           | 有独立 `d_todo` 行的子任务   |

例如“阅读某本书”可以周一 Done、周二重新安排并再次 Done，累计两次；全部读完再归档。归档不会自动把累计次数变成 1，也不要求一定先做过一次。

## 页面能力边界

Inbox 用于先收集再整理：没有普通集合的重命名 / 删除 / 展示归档菜单，事项也隐藏规划、完成 / 归档和置顶 / 置底操作。它仍可改名、设置链接、编辑草稿 / 看板、移动和删除；桌面难度控件也会渲染。移动目标只包含其他非 Inbox 集合，不能通过该菜单移回 Inbox。

该版未提供 Todo 全文搜索、任务提醒通知、自动周期规则、执行日期历史表、集合嵌套或跨事项依赖。累计 `d_count` 只保存次数，无法还原每一次发生在哪一天。
