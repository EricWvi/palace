# Todo 集合与事项用例

[返回 Todo](README.md)。本页所有操作按当前用户隔离；集合数据写入 `d_collection`，事项操作写入 `d_todo`。

## T01：先收集一个事项

1. 进入 Inbox 或某个集合，在输入框输入非空标题。
2. 点击加号或按 Enter；中文输入法组合过程中 Enter 不提交。
3. 创建 `d_todo`，保存标题、当前 `collection_id`，`d_order` 取集合中未归档事项最大值加 1。
4. 清空输入框，新事项排到列表顶部。默认没有草稿 / 看板，尚未归档，未设置难度和日期。

Inbox 也接收 [Journey 开始体验](../journey/use-cases.md)自动创建的提醒；这里不需要先创建数据库集合。

## T02：建立、改名和删除集合

| 场景 | 操作与结果                                | 数据影响 / 边界                                                    |
| ---- | ----------------------------------------- | ------------------------------------------------------------------ |
| 创建 | New List 输入非空名称后提交；出现在导航中 | 新增 `d_collection`；没有固定预设“工作 / 个人 / Archive”等业务类型 |
| 改名 | 普通集合右上菜单 → Rename                 | 更新 `name`；所属 Todo 的 `collection_id` 不变                     |
| 删除 | 菜单 → Delete List → 确认                 | 先软删除集合，再软删除其全部 Todo，包括归档事项                    |

删除集合不把事项移入 Inbox。后端两次删除未包在同一事务里，也不清理 Todo 的正文和看板。界面说明“无法撤销”，没有集合恢复入口。集合列表没有拖动排序功能。

## T03：修改事项标题

在事项上下文菜单选择 Rename，输入新标题提交，更新 `d_todo.title`。首页 Today 与集合列表引用同一条事项；标题不是各页面分别维护的副本。

## T04：标注难度

桌面大屏标题下方显示四个点，对应容易、中等、困难、非常困难（1–4）。点击某一级写入 `difficulty`，再次点击当前级别写入 `-1` 取消难度。左侧色条和部分标题下划线随难度变化。

难度不改变排序或排期。“我的一天”候选排序使用累计次数，不使用难度。四点操作控件在小屏隐藏，不能把移动端也描述成具有同样的直接编辑入口。

## T05：附加或清除外部链接

菜单 Link 打开链接编辑框；提交非空值更新 `link`，清空走 `UnsetLink`。用户可以从标题 / 链接入口打开外部内容。链接只保存字符串，不抓取网页、不创建 Bookmark，也不建立 Journey 外键。

## T06：将事项置顶或置底

普通集合中的非首项可 Top，非末项可 Bottom。列表按 `d_order DESC` 显示；置顶取当前集合活动项最大值加 1，置底取最小值减 1（至少为 -1）。新建、恢复和移动也使用顶部排序值。

这是显式头尾排序，主事项列表没有任意拖动排序；不要与内部看板的拖动混淆。

## T07：在集合间整理事项

菜单 Move To → 选择另一个普通集合，更新 `collection_id` 并放到目标集合顶部。标题、链接、正文、看板、计划和累计次数留在同一事项上。

可从 Inbox 移出，但菜单排除 Inbox 作为目标。这意味着“回到 Inbox”不是此发布版的现有用户流程。

## T08：归档不再活跃的事项

普通事项菜单 Complete 经过确认后设置 `completed=true`，并把 `created_at` 改为当前时间，用于归档排序。活动列表不再显示它，Today 查询也排除它。

菜单依状态变化：当事项排在今天且还没 Done 时，先显示 Done；已经 Done 时显示 Undone 和 Complete；非今日事项可直接 Complete。归档不会执行 `d_count+1`，也不会清空计划、正文或看板。

## T09：查阅归档与恢复

1. 在普通集合菜单展开 Completed / 归档事项。
2. 归档记录按 `created_at DESC` 排列，展示标题、累计次数和日期；已有正文 / 看板仍可打开。
3. Restore 设置 `completed=false` 并放回原集合顶部；保留累计次数等其他字段。

恢复接口不重置 `done` 或 `schedule`，所以恢复后的 Today 归属仍由原日期决定。移动端归档区域嵌在非空活动列表分支里：若集合没有活动项，可能无法看到已有归档，这是界面限制，不代表归档数据不存在。

## T10：删除事项与批量清理归档

| 入口            | 前置条件与确认               | 实际效果                                  |
| --------------- | ---------------------------- | ----------------------------------------- |
| 活动事项 Delete | 上下文菜单，弹框确认         | 软删除当前 Todo                           |
| 归档事项 Delete | 归档条目的上下文菜单直接调用 | 软删除当前 Todo；该入口未增加同样的确认框 |
| Clear N todos   | 当前集合存在归档项，确认清理 | 软删除该集合全部 `completed=true` 事项    |

这三种删除都没有 UI 恢复流程；`draft`、`kanban` 指向的 `d_tiptap` 不随 Todo 自动删除。移植时要先决定材料保留语义，不能把旧版残留文档误认为新的独立笔记。

## 迁移核对

- 新建 → Inbox → 普通集合 → 置底 → 归档 → 恢复后，仍保持同一内容身份和所有材料。
- 有多个普通集合时，移动影响归属和顺序，不复制任务。
- 删除集合、删除一项、清理归档的影响范围各自明确。
- 用户名称为 Archive 的集合与 `completed` 状态分别保留。
