# 共享富文本编辑与版本历史

[返回总览](../README.md)。Quick Note、Todo 草稿、Journey 感想 / 摘录、Echoes、Bookmark cheatsheet、Blog、Journal 都复用同一套编辑器，正文集中存储在 `d_tiptap`。

## 正文与所属对象

所属业务表保存文档 ID，`d_tiptap` 保存 `content`（JSON）、`ts`（版本时间戳）、`history`（JSON 数组）。正文没有通用标题字段；各页面标题来自业务元信息或正文自己的 heading。

Todo 看板也使用此表，但 `content` 是列与卡片结构。不能把所有 `d_tiptap` 行直接用 Tiptap 解析；需要从引用位置或 JSON 结构识别。

## C01：撰写与排版

编辑器提供撤销 / 重做、标题、段落、无序 / 有序 / 任务列表、引用、代码块、粗体、斜体、删除线、行内代码、下划线、高亮、链接、上下标、文本对齐、分隔线、表情、图片和视频。支持嵌套任务列表与微信表情扩展，标题目录按 2 / 3 / 4 级 heading 导航。

工具条根据屏幕大小调整，高亮和链接在移动端有独立工具视图。只读预览与编辑模式复用文档结构。表情、视频等自定义节点需要迁移渲染支持，不能只保留纯文本。

编辑与部分只读视图提供明暗主题切换，初始参考系统色彩偏好；它修改页面主题，不写 `d_user` 的持久偏好字段。

## C02：自动保存与显式保存

| 操作                       | 写入                                           | 用户结果                               |
| -------------------------- | ---------------------------------------------- | -------------------------------------- |
| 编辑后每 5 秒同步          | 带 `prev=上次ts`、`curr=当前时间` 更新 content | 编辑器保持打开；成功后推进本地版本     |
| 点击保存 / Ctrl 或 Cmd + S | 有改动时 `prev=-1` 强制保存当前文档            | 保存成功后关闭；各页面触发各自刷新回调 |
| 无修改时保存退出           | 不提交正文更新                                 | 关闭编辑器                             |
| 离开 / 刷新页面            | 编辑器安装浏览器离开保护                       | 提示离开，不等于已经完成持久化         |

自动保存按 `(creator_id,id,ts=prev)` 匹配，无行更新返回 409；前端提示不同步并失效查询。**显式保存使用 `prev=-1` 跳过版本匹配**，因此整个流程不是协同编辑，也没有自动合并。不能宣称所有写入都保证不会覆盖其他端内容。

Journal 的正文保存后还更新 `d_entry.raw_text / word_count`；其他业务元信息通常不跟随正文变动自动更新。

## C03：放弃本次修改

工具条放弃动作将打开编辑器时传入的 `draft` 快照强制写回服务器，再关闭编辑器。因为自动保存可能已经写入中间状态，“放弃”本身是一次还原写入，不只是关掉弹框。

它不删除新建的业务记录 / 文档，也不清除本次上传的所有文件。此行为与多端编辑相遇时会覆盖当前内容，Palace 应单独定义自己的放弃与冲突策略。

## C04：查看历史、比较差异、恢复

历史按钮打开版本侧栏，显示版本号和本地时间；选一项可预览历史正文以及与当前正文的差异。确认恢复后调用 `RestoreHistory`，把选中 content 写成当前正文并更新 `ts`，刷新编辑器数据。

`history` 是同一行的 `[{time,content}, ...]`。服务端在历史为空时尝试备份当前版本；强制保存后把保存结果加入历史。它不是每次 5 秒自动保存都追加快照，也不是数据库审计日志。恢复 handler 本身没有先保存被覆盖内容的独立备份步骤。

每日 02:30 的历史清理只保留近 7 天快照。不能承诺任意时间回溯、完整逐键历史或删除业务对象后从历史恢复。

## 迁移核对

- 每个业务正文引用和自定义节点可解析，正文样式、媒体和表情不丢失。
- 自动保存、显式保存、放弃、冲突、恢复各自的实际效果可解释。
- 只导入仍存在的历史，不虚构已被清理版本。
- 内容派生数据（Journal 搜索与字数）能在恢复 / 导入后重建。
