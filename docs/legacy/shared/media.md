# 共享媒体与附件

[返回总览](../README.md)。上传文件不直接存进业务正文或数据库二进制字段：对象存储保存文件，`d_media` 保存访问映射，业务对象 / 文档持有 URL。

## C05：上传头像、作品封面和正文媒体

Profile 可上传头像，Journey 可上传封面，富文本编辑器可上传图片和视频。上传使用 `/api/upload` 的 multipart `photos` 字段，返回每个文件的 UUID link；前端生成 `/api/m/<link>` 形式的访问地址。

图片 / 视频编辑器上传函数限制单文件 50 MB，提供进度和取消处理；图片上传节点一次最多 9 个。这些是对应前端入口的限制，不是对所有上传接口的统一服务端限制承诺。

图片上传前尝试浏览器压缩，失败时回退上传原文件；数据库中的对象对应实际上传结果，不能保证是相机原始无损文件。

后端把文件上传到 MinIO / S3 兼容存储，取得对象 key 和签名 URL，再写 `d_media`：拥有者、UUID `link`、`key`、`presigned_url`、最近签名时间。

## C06：打开已有媒体

访问 `/api/m/<link>`，后端以当前用户和 UUID 查询媒体映射，然后 302 跳到签名地址。图片、视频、头像和封面复用这一映射。缺少记录或签名地址时返回 404。

后台每天 02:15 查找距上次签名约 5 天以上的媒体并重新签名。文档中保存稳定的应用地址，因此不必每次签名更新都修改正文。

## C07：移除显示与删除文件

正文删掉 image / video 节点、资料清除头像、作品更换封面，只能说明引用发生变化，不等于存储对象已清除。

后端另有 `DeleteMedia`：按当前用户和 UUID 查找，软删除媒体记录，再删除对象存储文件；批量处理中失败会跳过 / 记录，返回成功删除 ID。它不做跨正文 / 历史的引用计数扫描，也不是删除 Todo、手记或 Bookmark 时的统一级联流程。

## Palace 导入要保留什么

| 内容                     | 用途                                |
| ------------------------ | ----------------------------------- |
| 对象存储原文件           | 图片 / 视频 / 头像 / 封面的实际内容 |
| `d_media.link` 与 `key`  | 从旧正文 URL 找到原文件             |
| 正文当前值和历史中的 URL | 恢复所有仍需要展示的引用            |
| 业务表头像、封面 URL     | 恢复正文以外的媒体                  |
| 用户归属                 | 维持私有访问范围                    |

签名 URL 会过期，不能当作永久迁移源；媒体可能还有外部 URL，不是所有图片都能在 `d_media` 找到。迁移应建立旧 URL 到新附件身份的映射，并检查共享引用、缺失文件和软删除项，不按某一条业务记录的删除状态直接清掉所有同 URL 文件。
