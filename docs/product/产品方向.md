# 产品方向

## 核心判断

Palace 不以“功能页面”作为产品的主要组织方式，而以“某一天发生了什么”作为用户进入产品后的第一视角。

用户不需要先判断应该进入睡眠、音乐、照片、Journal 还是对话页面；用户先看到当天的内容，再从对应卡片进入详情。

## 核心体验

1. 打开产品，看到一个日期对应的时间线。
2. 时间线上按时间顺序展示当天发生或记录的内容。
3. 每种内容都以卡片出现，卡片有统一的浏览方式，但保留自己的信息重点。
4. 点开卡片，在详情中查看该内容的完整信息。
5. 通过左右滑动或日期切换浏览其他日期。

## 首批内容类型

| 内容类型 | 时间线卡片 | 详情示例 |
| --- | --- | --- |
| 睡眠 | 睡眠时间、时长、质量摘要 | 睡眠日历、历史记录、统计信息 |
| 对话 | 对话标题、来源、对话发生时间、摘要 | 完整对话内容 |
| 歌曲 | 歌曲名、艺人、播放时间 | 流派、艺人、专辑及相关信息 |
| 照片 | 缩略图、拍摄时间、地点摘要 | 原图、地点、拍摄时间及其他元数据 |
| Journal | 标题或正文摘要、时间、标签 | 正文、地点、时间、Tag |

这张表描述的是产品体验，不限制底层数据一定使用同一种存储结构。不同内容可以拥有不同的详情模型，但必须能够出现在统一时间线上。

## 设计原则

### 时间线优先

时间线是默认入口和跨内容类型的统一索引。专门的功能入口可以存在，但不应取代时间线作为主体验。

### 卡片是入口，不是完整内容

卡片只展示足以让用户理解“这是什么、什么时候发生”的信息。完整内容、复杂操作和历史视图放入卡片详情。

### 统一骨架，保留个性

所有卡片共享日期、时间、类型和打开详情的基本交互；详情区域根据内容类型展示真正有价值的信息，不为了统一而把所有内容强行做成同一套字段。

### 记录与视图分离

内容本身是一条记录；它在时间线中的卡片是该记录的一种视图。以后增加新的入口或筛选方式，不应复制一份内容。

### 先记录，再组织

导入或创建内容时，优先保证内容和发生时间被保存。分类、标签、地点和跨内容关联可以逐步补充，不应阻塞内容进入时间线。

## 当前能力的产品化方向

当前已有“对话导入”能力。后续它应从独立的会话列表入口，演进为时间线中的“对话卡片”：

- 导入成功后，在对应的对话发生时间位置生成对话卡片。
- 卡片展示标题、来源和简短摘要。
- 点击卡片后查看完整对话内容。
- 原有对话内容的树状结构、来源和导入语义继续由对话详情负责。
- 对话不因为进入时间线而被简化成普通文本，也不需要为时间线复制一份内容。
