# 跨端形态

## 移动端

移动端主页面采用日历风格，以一个日期为主要浏览范围：

- 默认打开当天。
- 左滑查看前一天，右滑查看后一天。
- 当前日期的内容按时间顺序形成时间线。
- 点击卡片进入详情；详情内部可以承载内容类型专属的历史视图，例如睡眠日历。
- 创建或导入内容后，返回对应日期的时间线，并突出新生成的卡片。

移动端的重点是连续浏览和快速回看，不要求用户记住功能页面的位置。

## Web 端

Web 端同样以当天内容为主要展示区域，但可以提供更明显的辅助入口：

- 日期导航和日历选择。
- 内容类型筛选。
- 搜索、标签和地点等跨日期入口。
- 导入、创建和设置等操作入口。
- 在较大屏幕上使用更丰富的卡片布局或详情面板。

这些入口是时间线的补充，不应把产品重新组织成互相孤立的“睡眠页”“照片页”“Journal 页”和“对话页”。筛选结果仍然应以卡片列表或时间线的方式展示，并能进入同一套详情。

## 统一交互契约

无论移动端还是 Web 端，每张卡片都应支持：

1. 识别内容类型。
2. 看到时间线摘要。
3. 打开完整详情。
4. 从详情回到原来的日期和位置。

端之间可以不同地排版、排序和提供快捷操作，但不应改变内容的时间语义与详情含义。
