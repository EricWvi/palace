# 环境变量

本文汇总当前代码读取或依赖的环境变量。生产服务的配置入口是
`apps/palace-server/src/main.rs` 和共用的 `server.rs`；未列出的常见变量（例如 `RUST_LOG`）当前不会被
Palace 主程序读取。

## 生产服务

| 变量 | 必填 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `PALACE_DATABASE_URL` | 是 | 无 | PostgreSQL 连接 URL。服务启动时使用它连接数据库，并执行 SQL migrations。 |
| `PALACE_ORIGIN` | 是 | 无 | 浏览器访问 Palace 的外部 origin。必须是没有路径、查询、片段或用户信息的 HTTPS origin，例如 `https://palace.example.com/`。它用于 OIDC 回调地址和 Origin 校验。 |
| `PALACE_OIDC_ISSUER` | 是 | 无 | OIDC provider 的 issuer URL。启动时用于发现 provider metadata；生产环境应配置为可信的 Authelia issuer。 |
| `PALACE_OIDC_CLIENT_ID` | 是 | 无 | OIDC confidential client 的 client ID。 |
| `PALACE_OIDC_CLIENT_SECRET` | 是 | 无 | OIDC confidential client secret。它只在服务端使用，不会写入浏览器 Session。 |
| `PALACE_SESSION_KEY` | 是 | 无 | 32 字节随机部署密钥的标准 Base64。用于派生 Palace cookie secret，以及加密数据库中的 refresh credential。所有服务实例必须持有同一值；更换它会使现有 Session 无法继续认证。 |
| `PALACE_LISTEN` | 否 | `127.0.0.1:8080` | HTTP 监听地址，格式为 `host:port`。 |
| `PALACE_WEB_DIST` | 否 | `apps/palace-web/dist` | 前端静态文件目录；Docker 镜像中为 `/app/dist`。 |
| `PALACE_TIMEZONE` | 否 | `Asia/Shanghai` | 部署所在的本地时区：服务日志按它记录时间，笔记 frontmatter 和文章导入中只有日期的 `date` 按它的当天 00:00 解释，文章的发布日期也按它写回。Session 和业务持久化的 epoch 时间仍按统一时间数值保存。 |
| `PALACE_NOTES_DIR` | 否 | 无 | 摘星笔记所在的 Markdown 文件夹（容器内路径）。服务读取并监听其根目录下的 `.palace-cache.json`，用容器内的 `rg` 搜索正文，从不写入该文件夹，可以只读挂载。未设置时笔记列表为空。见下文“摘星笔记”。 |
| `PALACE_JOTTINGS_DIR` | 否 | 无 | 札记所在的文件夹（容器内路径），必须位于一个 Git 工作区内，可以是仓库的子目录。服务读取当前分支的 commit，从不写 `.git`，只在其下的 `inbox/` 写入上传的札记。未设置时札记功能不可用；已设置但不在 Git 工作区内、HEAD 处于 detached 状态或分支还没有 commit 时启动失败。见下文“札记”。 |
| `PALACE_S3_ENDPOINT` | 否 | 无 | 媒体文件所在 S3 兼容存储的 endpoint URL，`http` 或 `https`，例如 `https://minio.example.com`。与下面五个 `PALACE_S3_*` 必须同时提供或同时不提供，见下文“媒体存储”。 |
| `PALACE_S3_REGION` | 否 | 无 | S3 region；MinIO 可使用 `us-east-1`。 |
| `PALACE_S3_BUCKET` | 否 | 无 | 存放媒体文件的 bucket，需事先创建。 |
| `PALACE_S3_ACCESS_KEY_ID` | 否 | 无 | S3 access key。 |
| `PALACE_S3_SECRET_ACCESS_KEY` | 否 | 无 | S3 secret key，只在服务端使用，不写入日志。 |
| `PALACE_S3_PATH_STYLE` | 否 | 无 | `true` 使用 path-style 寻址（MinIO 通常需要），`false` 使用 virtual-hosted style。 |
| `PALACE_MEDIA_MAX_BYTES` | 否 | `52428800`（50 MiB） | 单个媒体文件的字节上限，正整数；只在启用媒体存储时生效，文章导入中的每个文件也受它约束。 |
| `PALACE_ARTICLE_MAX_BYTES` | 否 | `268435456`（256 MiB） | 一次文章导入（正文加全部嵌入文件）的请求体上限，正整数；只在启用媒体存储时生效，未启用时文章导入只能不带文件。 |
| `PALACE_S3_PUBLIC_ENDPOINT` | 否 | 同 `PALACE_S3_ENDPOINT` | 浏览器访问对象存储的 endpoint，`http` 或 `https`。媒体读取的签名 URL 按它签名，写入和删除仍用 `PALACE_S3_ENDPOINT`。不属于上面六个“全有或全无”的变量，但只设置它而没有配置存储时启动失败。 |

## 摘星笔记

笔记是 Palace 之外维护的 Markdown 文件夹。每篇笔记的 frontmatter 必须有非空的 `title`，以及 `YYYY-MM-DD` 或带时区偏移的 RFC 3339 `date`；没有 frontmatter 或带 `draft: true` 的 `.md` 不是笔记，会被跳过。在宿主机上用 Palace 仓库提供的脚本生成 cache（需要 Node 24 与 `rg`）：

```bash
node scripts/notes-cache.ts /path/to/notes
```

脚本按 ripgrep 的规则枚举 `*.md`（尊重 `.gitignore`、`.ignore`，跳过隐藏文件，不要求是 git 仓库），校验所有笔记，任何一篇不合格都会列出全部问题并以非零状态退出，不改动原有 cache；全部合格时以 rename 原子替换 `.palace-cache.json`，并报告跳过的文件数。什么时候运行脚本（手动、git hook 或定时任务）由笔记的维护流程决定。

挂载整个文件夹，不要单独挂载 cache 文件：单文件 bind mount 绑定的是 inode，原子替换后的新文件在容器里不可见。

```bash
docker run -v /path/to/notes:/notes:ro -e PALACE_NOTES_DIR=/notes ...
```

服务端监听文件夹根目录的文件事件，另外每分钟比较一次 cache 的修改时间，覆盖不触发 inotify 的网络挂载。cache 损坏或缺失时保留已加载的笔记并记录错误日志。笔记正文每次打开时从文件读取，改正文不需要重新生成 cache；标题和日期以 cache 为准。

## 札记

札记文件夹必须在一个 Git 仓库里。挂载整个仓库（包括 `.git`），并让 `PALACE_JOTTINGS_DIR` 指向其中的札记目录；容器需要对 `inbox/` 有写权限：

```bash
docker run -v /path/to/repo:/repo -e PALACE_JOTTINGS_DIR=/repo/jottings ...
```

- 服务端监听 `.git` 中 HEAD 与分支 ref 的文件事件，HEAD 指向新的 commit 时与该 commit 对账；另外每分钟读一次 HEAD 作为兜底，覆盖不触发 inotify 的网络挂载。HEAD 没变时不读取任何文件。
- 服务端以容器用户写入 `inbox/<id>.md`。宿主机上的 Agent 需要能移动和修改这些文件，部署时让两边的 UID 一致或共用一个组。
- 仓库属主与容器用户不同时也能打开：服务端只读 Git 对象，不应用仓库中的配置。
- 文件格式、commit 规则与同步接口见[札记](../features/jottings/README.md)。

## 媒体存储

媒体文件的内容存放在 S3 兼容对象存储中，数据库只保存归属和对象位置；接口只返回 Palace 生成的媒体 ID。六个 `PALACE_S3_*` 变量必须全部提供才启用媒体存储；全部不提供时服务正常启动，所有媒体接口（上传、读取、删除）返回 503，带文件的文章导入也返回 503；只提供一部分（空值视为未提供）时启动失败，并列出缺少的变量。启动时只构建客户端、不连接存储，bucket 或凭据错误会在第一次上传时以 503 暴露。

新对象的 key 为 `<owner_id>/<media_id>`。一个部署只使用一个 bucket；迁移存储时应整体复制 bucket 并保持 key 不变，再切换配置。

`GET /api/media/{id}` 不经 Palace 转发字节，而是 302 跳转到对象存储的签名 URL，所以浏览器必须能访问对象存储。签名覆盖主机名：服务端通过容器内部地址（例如 `http://minio:9000`）访问存储时，设置 `PALACE_S3_PUBLIC_ENDPOINT` 为浏览器能访问的地址（例如 `https://minio.example.com`）。bucket 不需要公开读，也不需要 CORS。

```bash
export PALACE_S3_ENDPOINT='https://minio.example.com'
export PALACE_S3_REGION='us-east-1'
export PALACE_S3_BUCKET='palace'
export PALACE_S3_ACCESS_KEY_ID='palace'
export PALACE_S3_SECRET_ACCESS_KEY='store-this-in-a-secret-manager'
export PALACE_S3_PATH_STYLE='true'
```

## 值格式与示例

`PALACE_SESSION_KEY` 必须解码为恰好 32 字节。可以使用 OpenSSL 生成随机值并转为标准
Base64：

```bash
openssl rand 32 | base64
```

示例配置：

```bash
export PALACE_DATABASE_URL='postgres://palace:password@127.0.0.1:5432/palace'
export PALACE_ORIGIN='https://palace.example.com/'
export PALACE_OIDC_ISSUER='https://auth.example.com'
export PALACE_OIDC_CLIENT_ID='palace'
export PALACE_OIDC_CLIENT_SECRET='store-this-in-a-secret-manager'
export PALACE_SESSION_KEY='replace-with-32-random-bytes-in-standard-base64'
export PALACE_LISTEN='127.0.0.1:8080'
export PALACE_TIMEZONE='Asia/Shanghai'
```

不要把 `PALACE_OIDC_CLIENT_SECRET`、`PALACE_SESSION_KEY` 或 `PALACE_S3_SECRET_ACCESS_KEY` 提交到 Git、写入日志、写入
业务同步数据或放进浏览器 cookie。反向代理负责终止 HTTPS，并将请求转发到
`PALACE_LISTEN`。

## 本地测试 server

直接运行，Taskfile 会为该入口配置默认的允许 origin：

```bash
task run:server
```

默认允许 Vite 前端的 `http://127.0.0.1:5173` origin，再运行 `task run:web` 即可。
详见 [Web 开发与验证](../frontend/开发与验证.md)。

`task run:server` 默认从 `../flomo/jottings` 读取札记，Git 仓库根目录是 `../flomo`，可用
`PALACE_JOTTINGS_DIR` 覆盖。启动、监听和按 commit 索引不修改札记文件或 `.git`；索引写入本项目的
PostgreSQL。只有 `POST /api/jottings` 上传新札记时，才会在札记目录下写入 `inbox/<id>.md`。

默认访问 `http://127.0.0.1:8080`，根路径跳转到 `/api/me`。测试入口固定使用 `local-test@palace.test`，不提供登录、回调或退出接口，不创建 Session，不读取 cookie 或 Bearer token，也不启动 Authelia。所有业务请求都归属于这个测试用户。

固定用户通过稳定的本地 identity pair 保存到 PostgreSQL，重启后复用同一个 Owner。每次启动创建 `postgres:17-alpine` testcontainer，将容器端口 `5432` 固定映射到宿主机 `15432` 并执行 migrations；数据库文件保存在项目根目录 `.data/postgres/pgdata`。正常退出停止并移除容器，保留数据。需要本地已有该镜像及可用的 Docker/Podman API，缺少镜像直接报错。

数据库客户端连接信息：host `127.0.0.1`、port `15432`、database `palace`、user `postgres`、password `palace-test`。也可直接使用：

```bash
psql 'postgres://postgres:palace-test@127.0.0.1:15432/palace'
```

该端口固定，不提供环境变量覆盖；如果被占用，启动会失败。服务退出时容器和端口映射一起移除，修改的数据随数据库文件保留。使用远端 Docker/Podman 时，host 改为容器引擎所在机器。

| 变量 | 默认值 | 测试入口用途 |
| --- | --- | --- |
| `PALACE_LISTEN` | `127.0.0.1:8080` | HTTP 监听地址。该入口无需认证，默认仅供本机联调。 |
| `PALACE_ORIGIN` | `http://127.0.0.1:5173`（由 `Taskfile.yml` 配置） | 写请求允许的 Origin；不得带路径、查询、片段或凭证。联调前端地址变更时可在执行 task 时覆盖。 |
| `PALACE_TIMEZONE` | `Asia/Shanghai` | 日志时区，也用于解释笔记和文章只有日期的 `date`。 |
| `PALACE_NOTES_DIR` | `../notes/writings`（由 `Taskfile.yml` 配置） | 摘星笔记文件夹，规则与生产服务相同；直接运行二进制且未设置时没有笔记。 |
| `PALACE_JOTTINGS_DIR` | `../flomo/jottings`（由 `Taskfile.yml` 配置） | 札记文件夹，规则与生产服务相同；直接运行二进制且未设置时札记功能不可用。 |
| `PALACE_S3_*`、`PALACE_MEDIA_MAX_BYTES`、`PALACE_ARTICLE_MAX_BYTES` | 无 | 媒体存储，规则与生产服务相同；未设置时媒体接口返回 503。 |

`PALACE_DATABASE_URL`、`PALACE_SESSION_KEY`、所有 `PALACE_OIDC_*` 和 `PALACE_TEST_OIDC_PORT` 均不由测试入口读取。无需域名、测试证书或 HTTPS 代理。生产入口继续要求真实 OIDC 和 Session 配置，不提供固定用户模式。

写请求仍须携带匹配的 Origin，例如：

```bash
curl http://127.0.0.1:8080/api/me
curl -X POST http://127.0.0.1:8080/api/sync \
  -H 'Origin: http://127.0.0.1:5173' \
  -H 'Content-Type: application/json' \
  -d '[]'
```

数据目录相对于编译时项目根目录，不受启动工作目录影响，已被 Git 忽略；`server.lock` 防止同时使用同一份数据。删除数据库文件会丢失测试数据，应先停止 server。容器初始化使用数据库 `palace`、用户 `postgres`、测试密码 `palace-test`。

`task test:test-server` 使用独立临时目录验证 PostgreSQL 重建后的数据保留、并发启动拒绝，以及固定用户无需登录即可读写、重建 router 后复用身份、Origin 校验和 Owner 数据隔离，不读取或修改 `.data`。

以下变量不是 Palace 生产服务的配置，但会影响测试或测试容器：

Authelia 契约测试同样使用 testcontainers，并在测试代码中注入容器环境和 fixture 配置；
它们不是生产部署变量。

## 运行前检查

生产入口启动时，以下问题会直接导致服务失败：

- 缺少任一必填变量；
- `PALACE_ORIGIN` 不是合法的 HTTPS origin；
- `PALACE_SESSION_KEY` 不是合法 Base64，或解码后不是 32 字节；
- `PALACE_S3_*` 只提供了一部分（包括只设置了 `PALACE_S3_PUBLIC_ENDPOINT`），`PALACE_S3_ENDPOINT` 或 `PALACE_S3_PUBLIC_ENDPOINT` 不是 http(s) URL，`PALACE_S3_PATH_STYLE` 不是 `true`/`false`，或 `PALACE_MEDIA_MAX_BYTES`、`PALACE_ARTICLE_MAX_BYTES` 不是正整数；
- OIDC provider discovery 失败；
- 数据库连接或 migrations 失败。
