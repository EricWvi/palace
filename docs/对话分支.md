# 对话树与来源路径

每张卡片是一个 Conversation，拥有标题、来源和消息树；每个来源 Session 是一个独立 Path。
同一用户、来源网站下的 Session ID 不可重复，创建新会话不会再自动合并已有 Session。

## 接口

| 接口 | 输入或返回 |
| --- | --- |
| `POST /api/import`、`POST /api/import/file` | 创建 Conversation 及首条 Path；沿用标题、来源、Session ID、history、occurred_at、idempotency_key |
| `GET /api/conversations` | 卡片含 `session_ids`、`path_count`、默认 `path_id`、`head_message_id`、树消息总数及最大 `occurred_at` |
| `GET /api/conversations/{id}` | `conversation`（无 Session ID）、`messages`、`paths`；每个 Path 含身份、Session ID、末端、消息数、时间及 `original_link` |
| `POST /api/conversations/{id}/paths` | JSON：`session_id`、`history` 原始 JSON 字符串、`occurred_at` epoch 毫秒、`idempotency_key` |
| `PUT /api/conversations/{id}/paths/{path_id}` | JSON：`history`、`occurred_at`、`idempotency_key`；Session 身份保持不变 |
| `GET /api/conversations/{id}/paths/{path_id}` | 对应 Path 的完整消息数组 |
| `DELETE /api/conversations/{id}/paths/{path_id}` | 删除分支及不再被引用的消息；最后一个分支请删除整个对话 |
| `DELETE /api/conversations/{id}` | 原子删除整棵树及所有 Path、导入记录 |

所有导入响应含 `conversation_id`、`path_id`、`head_message_id`、创建和复用消息数量。
分支接口不接受标题、来源和 Owner；更新不接受 Session ID。重复 Session 返回 409 `session_already_exists`。

新分支需从根开始共享至少到一个 assistant 节点的完整前缀。更新必须上传完整 JSON，
只能追加或保持全部原历史，不能截短、改写或重排。比较严格使用原始 role/content，不做文本规范化。

`occurred_at` 是用户填写的发生时间；`created_at` 和 `updated_at` 是数据库记录的创建与更新时间。
同键同请求的幂等重试不改变时间；失败时消息和时间一起回滚。列表按最大 `occurred_at` 排序，
默认阅读路径按 `updated_at DESC, id DESC` 选择，前端以浏览器本地时区展示。

## 分支管理

主页面每张卡片菜单提供“分支管理”和“删除对话”。管理弹窗只显示 user 消息摘要，
单行省略；末端落在同一 user 节点的多个 Session 分别提供更新／删除。
树图使用 React Flow 与 Dagre 自上而下布局，根节点位于顶部，支持拖动画布、缩放与适应画布。
节点操作在鼠标悬停或键盘聚焦时显示；触屏设备保持可见。图组件按需加载，不阻塞会话列表。
新建分支时标题与来源禁用，更新时 Session ID 也禁用；这些字段不会包含在请求正文中。
更新的日期时间回填 Path 原 `occurred_at`，允许修改。分支和整棵对话删除都有明确确认弹窗。

“继续对话”位于阅读页底部，使用所选 Path 的来源链接；详情 URL 使用 `?path=PathID`。
阅读页在每个分叉点显示选择器；选择上游节点后，后续选择使用该子树内更新时间最新的 Path。
结束于内部节点的 Path 提供“在此结束 · Session ID”，相同消息路径的不同 Session 也分别可选。
时间相同时按 Path ID 降序稳定选择；选择不会拼接来自不同 Path 的后缀。

## 迁移

`0007_conversation_paths.sql` 针对现有单路径 Conversation 将 Session ID 移到新 Path，
保留 Conversation/Message 身份。多次旧导入使用最后创建的导入记录提供发生时间，最长消息链作为末端。
服务启动自动运行迁移；本地测试只在独立 PostgreSQL 容器运行，不修改用户数据。

## 验证

`task test:integration` 验证有数据迁移、跨 Owner 隔离、前缀复用、并发 Session 唯一性、
追加限制、幂等、失败回滚、共享节点删除和 HTTP 契约。
`task test:frontend` 验证逐节点切换、内部末端、管理操作及请求字段；
`npm run test:browser -w apps/palace-web` 验证真实浏览器中的嵌套切换、深链接刷新、
本地时间回填／修改、移动端弹窗边界和中英文单行省略。
浏览器测试默认使用 5173 端口；端口占用时可设置 `PALACE_BROWSER_TEST_PORT` 使用独立端口。
