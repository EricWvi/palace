# 环境变量

本文汇总当前代码读取或依赖的环境变量。生产服务的配置入口是
`apps/palace-server/src/main.rs` 和共用的 `server.rs`；未列出的常见变量（例如 `RUST_LOG`）当前不会被
Palace 主程序读取。

## 生产服务

| 变量 | 必填 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `PALACE_DATABASE_URL` | 是 | 无 | PostgreSQL 连接 URL。服务启动时使用它连接数据库，并执行 SQL migrations。 |
| `PALACE_ORIGIN` | 是 | 无 | 浏览器访问 Palace 的外部 origin。必须是没有路径、查询、片段或用户信息的 HTTPS origin，例如 `https://palace.example.com/`。它用于 OIDC 回调地址和 Origin 校验。 |
| `PALACE_OIDC_ISSUER` | 是 | 无 | OIDC provider 的 issuer URL。启动时用于发现 provider metadata；生产环境应配置为可信的 Authelia issuer。 |
| `PALACE_OIDC_CLIENT_ID` | 是 | 无 | OIDC confidential client 的 client ID。 |
| `PALACE_OIDC_CLIENT_SECRET` | 是 | 无 | OIDC confidential client secret。它只在服务端使用，不会写入浏览器 Session。 |
| `PALACE_SESSION_KEY` | 是 | 无 | 32 字节随机部署密钥的标准 Base64。用于派生 Palace cookie secret，以及加密数据库中的 refresh credential。所有服务实例必须持有同一值；更换它会使现有 Session 无法继续认证。 |
| `PALACE_LISTEN` | 否 | `127.0.0.1:8080` | HTTP 监听地址，格式为 `host:port`。 |
| `PALACE_WEB_DIST` | 否 | `apps/palace-web/dist` | 前端静态文件目录；Docker 镜像中为 `/app/dist`。 |
| `PALACE_TIMEZONE` | 否 | `Asia/Shanghai` | 服务日志使用的本地时区。Session 和业务持久化的 epoch 时间仍按统一时间数值保存。 |

## 值格式与示例

`PALACE_SESSION_KEY` 必须解码为恰好 32 字节。可以使用 OpenSSL 生成随机值并转为标准
Base64：

```bash
openssl rand 32 | base64
```

示例配置：

```bash
export PALACE_DATABASE_URL='postgres://palace:password@127.0.0.1:5432/palace'
export PALACE_ORIGIN='https://palace.example.com/'
export PALACE_OIDC_ISSUER='https://auth.example.com'
export PALACE_OIDC_CLIENT_ID='palace'
export PALACE_OIDC_CLIENT_SECRET='store-this-in-a-secret-manager'
export PALACE_SESSION_KEY='replace-with-32-random-bytes-in-standard-base64'
export PALACE_LISTEN='127.0.0.1:8080'
export PALACE_TIMEZONE='Asia/Shanghai'
```

不要把 `PALACE_OIDC_CLIENT_SECRET` 或 `PALACE_SESSION_KEY` 提交到 Git、写入日志、写入
业务同步数据或放进浏览器 cookie。反向代理负责终止 HTTPS，并将请求转发到
`PALACE_LISTEN`。

## 本地测试 server

直接运行，无需预先配置环境变量：

```bash
task run:test-server
```

联调 Vite 前端时，使用 `PALACE_ORIGIN=http://127.0.0.1:5173 task run:test-server`，
再运行 `task run:web`。详见 [会话前端](会话前端.md)。

默认访问 `http://127.0.0.1:8080`，根路径跳转到 `/api/me`。测试入口固定使用 `local-test@palace.test`，不提供登录、回调或退出接口，不创建 Session，不读取 cookie 或 Bearer token，也不启动 Authelia。所有业务请求都归属于这个测试用户。

固定用户通过稳定的本地 identity pair 保存到 PostgreSQL，重启后复用同一个 Owner。每次启动创建 `postgres:17-alpine` testcontainer，将容器端口 `5432` 固定映射到宿主机 `15432` 并执行 migrations；数据库文件保存在项目根目录 `.data/postgres/pgdata`。正常退出停止并移除容器，保留数据。需要本地已有该镜像及可用的 Docker/Podman API，缺少镜像直接报错。

数据库客户端连接信息：host `127.0.0.1`、port `15432`、database `palace`、user `postgres`、password `palace-test`。也可直接使用：

```bash
psql 'postgres://postgres:palace-test@127.0.0.1:15432/palace'
```

该端口固定，不提供环境变量覆盖；如果被占用，启动会失败。服务退出时容器和端口映射一起移除，修改的数据随数据库文件保留。使用远端 Docker/Podman 时，host 改为容器引擎所在机器。

| 变量 | 默认值 | 测试入口用途 |
| --- | --- | --- |
| `PALACE_LISTEN` | `127.0.0.1:8080` | HTTP 监听地址。该入口无需认证，默认仅供本机联调。 |
| `PALACE_ORIGIN` | 实际监听地址对应的 HTTP origin | 写请求允许的 Origin，可设为 HTTP 或 HTTPS；不得带路径、查询、片段或凭证。 |
| `PALACE_TIMEZONE` | `Asia/Shanghai` | 日志时区。 |

`PALACE_DATABASE_URL`、`PALACE_SESSION_KEY`、所有 `PALACE_OIDC_*` 和 `PALACE_TEST_OIDC_PORT` 均不由测试入口读取。无需域名、测试证书或 HTTPS 代理。生产入口继续要求真实 OIDC 和 Session 配置，不提供固定用户模式。

写请求仍须携带匹配的 Origin，例如：

```bash
curl http://127.0.0.1:8080/api/me
curl -X POST http://127.0.0.1:8080/api/sync \
  -H 'Origin: http://127.0.0.1:8080' \
  -H 'Content-Type: application/json' \
  -d '[]'
```

数据目录相对于编译时项目根目录，不受启动工作目录影响，已被 Git 忽略；`server.lock` 防止同时使用同一份数据。删除数据库文件会丢失测试数据，应先停止 server。容器初始化使用数据库 `palace`、用户 `postgres`、测试密码 `palace-test`。

`task test:test-server` 使用独立临时目录验证 PostgreSQL 重建后的数据保留、并发启动拒绝，以及固定用户无需登录即可读写、重建 router 后复用身份、Origin 校验和 Owner 数据隔离，不读取或修改 `.data`。

## 测试与容器

以下变量不是 Palace 生产服务的配置，但会影响测试或测试容器：

| 变量 | 使用位置 | 用途 |
| --- | --- | --- |
| `DOCKER_HOST` | `crates/db/tests/postgres.rs`、backend 集成测试及 testcontainers | 指定 Docker API endpoint；也可指向 Podman 的 Docker-compatible socket。 |
| `POSTGRES_PASSWORD` | PostgreSQL testcontainers | 测试容器内 `postgres` 用户的密码。测试代码会固定注入测试值。 |
| `POSTGRES_DB` | PostgreSQL testcontainers | 测试容器创建的数据库名。测试代码会固定注入测试值。 |

集成测试要求本地已经存在 `postgres:17-alpine` 镜像，不会因为缺少镜像主动下载。真实
Authelia 契约测试同样使用 testcontainers，并在测试代码中注入容器环境和 fixture 配置；
它们不是生产部署变量。

## 运行前检查

生产入口启动时，以下问题会直接导致服务失败：

- 缺少任一必填变量；
- `PALACE_ORIGIN` 不是合法的 HTTPS origin；
- `PALACE_SESSION_KEY` 不是合法 Base64，或解码后不是 32 字节；
- OIDC provider discovery 失败；
- 数据库连接或 migrations 失败。
