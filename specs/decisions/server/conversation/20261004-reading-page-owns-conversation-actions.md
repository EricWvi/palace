# 对话在摘星阅读页阅读与管理，删除后回到进入来源

对话的阅读与管理从会话收藏页迁到「摘星」的对话阅读页：标题、来源、Path 消息数和“继续对话”集中在页首，正文以书页式排版展示，分叉写成一句可点击的文字；编辑、分支管理和删除收进标题旁悬停才出现的 `···` 菜单。删除整个对话后回到进入阅读页的来源，删除单个 Path 时同时删除它对应的 Moment，阅读页改为展示剩余的 Path。

当前为 `approved`，已通过评审，核心测试用例见[对话阅读页](../../../test-cases/server/conversation/reading-page.md)。继承[Conversation 承载树，Path 承载来源 Session](20260919-conversation-tree-and-session-paths.md)与[卡片菜单统一更新 Conversation 标题与来源](20260919-menu-action-edits-conversation-metadata.md)的数据与接口语义，只修改操作入口、阅读界面和操作后的落点。涉及 `apps/palace-web` 的阅读页、分支管理、编辑与删除对话框；服务端接口不变。页面地址与来源参数见[Web 导航根决策](../../web/navigation/0-text-nav-day-routes-and-moment-opening.md) D3，视觉参照为 `docs/design/2.1-moment-conversation.html`。

## 继承与修改

| 前序约定 | 本次决定 |
| --- | --- |
| 阅读界面始终展示一个真实 Path，不拼接不属于任何 Path 的消息序列 | 继承，不变 |
| 详情初次打开选择 `updated_at DESC, id DESC` 第一条 Path，链接可指定 Path | 继承；从时间线进入时链接总是指定该 Moment 的 Path |
| 每个分叉点有选择器；内部末端提供“在此结束 · Session ID” | 修改：分叉写成一句文字，选项含义不变，见 D2 |
| 底部“继续对话”对应当前 Path 的来源链接 | 修改：移到页首元信息行末尾，仍唯一对应当前 Path |
| 卡片菜单包含“分支管理”“编辑会话”“删除对话” | 修改：会话收藏页移除，三项操作移到阅读页标题菜单，见 D3 |
| 管理弹窗只投影 user 节点；更新、删除按 Path 提供 | 继承，不变；弹窗从阅读页打开 |
| 删除 Path 只清理失去引用的消息；最后一个 Path 通过删除对话删除 | 继承；补充删除后的界面落点，见 D4、D5 |
| 编辑保存后标题、来源和原始链接在全部投影中一致可见 | 修改：标题只作用于当前 Path，来源作用于全部 Path；投影清单改为本页与时间线卡片，见 D6 |

## D1：阅读页的页首与正文

页首自上而下：

1. 可选的返回链接「← M 月 D 日」（来源规则见 Web 导航根决策 D3）。
2. 当前 Path 的标题（标题属于 Path，见[标题从 Conversation 移到 Path](20261005-title-belongs-to-path.md)），用展示字体，与时刻页日期标题处在同一高度；切换 Path 后随之改变。
3. 元信息行：`来源 · N 条消息 · 继续对话 ↗`。N 是当前 Path 的消息数，切换 Path 后随之变化；“继续对话”是当前 Path 的原始链接，在新窗口打开。

正文是一列消息，不使用聊天气泡：

- 每条消息上方是说话人小标签，user 为“你”，assistant 为来源名称（如 ChatGPT）。
- 正文使用内容字体（`--font-content`，系统字体）；user 消息放在浅色底块中，assistant 消息不加底色，两者都左对齐。
- Markdown 展示规则不变：GFM、不执行原始 HTML、不加载远程图片、链接在新窗口打开。

不再显示 Session ID、“会话存档”一类标签和底部页脚。

## D2：分叉写成一句文字

在每个分叉点下方显示一行小字：“此处分为 K 支：选项 · 选项 · …”。

- 普通选项以该分支下一条消息的开头文字命名，过长时截断；当前选中的选项带 accent 色下划线。
- Path 在此处的内部节点结束时，选项为“在此结束”；同一末端有多个 Session 时，分别显示“在此结束 · Session ID”。
- 选择一项后，替换其后的全部消息，Path 选择规则与前序决策相同；地址中的 `path` 以替换历史记录的方式更新。

这只是把选择器换成文字，选项集合、排序和选择后的 Path 解析都不变。

## D3：管理操作收进标题菜单

标题右侧有一个 `···` 按钮，显示规则遵循 Web 导航根决策 D5。菜单项依次为：

| 菜单项 | 行为 |
| --- | --- |
| 编辑对话 | 打开编辑对话框：标题只改当前 Path，来源改整个 Conversation，见标题归属决策 D3 |
| 分支管理 | 打开分支管理弹窗，规则同前序决策 D3 |
| 删除对话 | 打开确认弹窗，确认后删除整个 Conversation |

界面文案统一使用“对话”，不再使用“会话”。菜单在阅读页上，因此不存在“卡片导航与输入控件冲突”的问题；编辑仍使用对话框而不是原位编辑，以保留一次保存只有一个成功或失败结果的约定。

## D4：删除整个对话后回到进入来源

| 进入方式 | 删除成功后 |
| --- | --- |
| 从时刻进入（地址带 `date`） | 跳到 `/?date=…`，回到原来的日期 |
| 从摘星进入 | 跳到摘星入口页；入口页确定前不会出现此情况 |
| 直接打开链接（没有 `date`） | 跳到 `/` |

跳转使用替换历史记录的方式，后退不会回到已删除对话的地址。删除失败时留在原页并显示错误，可以重试。

## D5：删除单个 Path 时删除其 Moment，阅读页展示剩余 Path

删除 Path 的服务端行为不变：按 Moment 根决策 D3，在同一事务中删除该 Path、它的 Moment 以及失去引用的消息。界面落点如下：

- 阅读页留在原 Conversation，改为展示剩余 Path 中按前序规则选出的那一条，并更新地址中的 `path`。
- 若删除的是读者来时对应的 Moment，返回链接仍然回到原来的日期，只是不再定位到这个 Moment；该日期的时间线上它已经消失。
- 只剩一个 Path 时，分支管理不提供删除 Path，最后一个 Path 通过“删除对话”删除（继承前序约定）。

## D6：编辑后的投影

编辑对话保存成功后，以下投影都要观察到新值，不要求刷新页面：

- 阅读页：当前 Path 的标题、元信息行中的来源、说话人标签中的来源名称和“继续对话”链接。
- 时间线：被编辑 Path 的卡片显示新标题；该 Conversation 全部 Path 的卡片显示新来源。其他 Path 的标题不变。

## 不变量

1. 阅读页展示的消息序列总是某一条真实 Path 的完整序列。
2. 元信息行的消息数与“继续对话”链接都属于当前 Path。
3. 管理操作只出现在阅读页的标题菜单中，会话收藏页不再存在。
4. 删除对话成功后，历史记录中不保留指向该对话的当前条目。
5. 删除 Path 后不留下没有详情的 Moment，阅读页也不展示已删除的 Path。
6. 编辑保存成功后，阅读页与时间线卡片上同一 Path 的标题一致，全部 Path 的来源一致。

## 为什么不是这些替代方案

| 替代方案 | 优势 | 本次取舍 |
| --- | --- | --- |
| 保留会话收藏页及其卡片菜单 | 改动最小 | 与“时间线优先”的产品方向冲突；摘星入口页尚未设计，旧列表会在 Moment 根决策第 4 步移除 |
| 管理操作放在时间线卡片上 | 不用进入详情 | 卡片只回答“是什么、何时发生”；对话在时间线上可能有多张 Path 卡片，删除对话的作用范围不直观 |
| 保留聊天气泡 | 与来源网站相似 | 左右摆动的气泡不适合回看和摘录；书页式排版与原型风格一致 |
| 保留分叉下拉选择器 | 现成组件 | 下拉框是全页最重的控件，选项内容藏在弹出列表里；一句文字可以直接看到各分支的开头 |
| 删除对话后总是回到 `/` | 规则简单 | 从某一天进入的读者会被带到今天，失去刚才浏览的位置 |
| 删除 Path 后回到时间线 | 与删除对话一致 | Conversation 仍然存在，读者多半还要继续看其他分支 |

## 本决策未解决的问题

- **摘星入口页**：从摘星进入时的地址形式与删除后的落点，待摘星根决策确定后补充。
- **消息时间**：消息本身没有时间戳，阅读页不显示每条消息的时间。
- **阅读位置**：长对话的滚动位置是否在切换 Path 或返回后恢复，暂不承诺。

## 落地顺序

1. **阅读页改版**：按 D1、D2 重排页首和正文，数据接口不变。完成条件：现有逐节点切换、内部末端、深链接测试改写后通过。
2. **管理菜单迁移**：标题菜单承载三项操作，删除会话收藏页卡片菜单。完成条件：编辑、分支管理、删除的组件测试从卡片菜单迁到标题菜单。
3. **删除落点**：按 D4、D5 处理跳转与 Path 切换。完成条件：不变量 4、5 有浏览器测试。

服务端接口、数据模型和导入语义在全部阶段保持不变。
