# 对话在摘星阅读页阅读与管理，删除后回到进入来源

对话的阅读与管理从会话收藏页迁到「摘星」的对话阅读页：当前 Path 的标题、来源、消息数和“继续对话”集中在页首，正文以书页式排版展示，分叉写成一句可点击的文字；编辑、分支管理和删除收进标题旁悬停才出现的 `···` 菜单。删除整个对话后回到进入阅读页的来源；删除单个 Path 时同时删除它的 Moment，阅读页改为展示剩余的 Path。

当前为 `implemented`，核心测试用例见[对话阅读页](../../../test-cases/server/conversation/reading-page.md)。继承[Conversation 承载树，Path 承载来源 Session](20260919-conversation-tree-and-session-paths.md)与[卡片菜单统一更新 Conversation 标题与来源](20260919-menu-action-edits-conversation-metadata.md)的数据与接口语义，只修改操作入口、阅读界面和操作后的落点；标题归属由后续的[标题从 Conversation 移到 Path](20261005-title-belongs-to-path.md)决定。页面地址与来源参数见[Web 导航根决策](../../web/navigation/0-text-nav-day-routes-and-moment-opening.md) D3，视觉参照为 `design/2.1-moment-conversation.html`。会话收藏页已移除。

## 继承与修改

| 前序约定 | 本决定 |
| --- | --- |
| 阅读界面始终展示一个真实 Path，不拼接不属于任何 Path 的消息序列 | 继承，不变 |
| 详情初次打开选择 `updated_at DESC, id DESC` 第一条 Path，链接可指定 Path | 继承；从时间线进入时链接总是指定该 Moment 的 Path |
| 每个分叉点有选择器；内部末端提供“在此结束 · Session ID” | 修改：分叉写成一句文字，选项以 Path 标题命名，内部末端不再单独写作“在此结束”，见 D2 |
| 底部“继续对话”对应当前 Path 的来源链接 | 修改：移到页首元信息行末尾，仍唯一对应当前 Path |
| 卡片菜单包含“分支管理”“编辑会话”“删除对话” | 修改：会话收藏页移除，三项操作移到阅读页标题菜单，见 D3 |
| 管理弹窗只投影 user 节点；更新、删除按 Path 提供 | 继承，不变；弹窗从阅读页打开 |
| 删除 Path 只清理失去引用的消息；最后一个 Path 通过删除对话删除 | 继承；补充删除后的界面落点，见 D4、D5 |
| 编辑保存后标题、来源和原始链接在全部投影中一致可见 | 修改：标题只作用于当前 Path，来源作用于全部 Path；投影为本页与时间线卡片，见 D6 |

## D1：阅读页的页首与正文

页首自上而下：

1. 可选的返回链接「← M 月 D 日」（来源规则见 Web 导航根决策 D3）。
2. 当前 Path 的标题，用展示字体，与时刻页日期标题处在同一高度；切换 Path 后随之改变，浏览器标签页标题也是它。
3. 元信息行：`来源 · N 条消息 · 继续对话 ↗`。N 是当前 Path 的消息数；“继续对话”是当前 Path 的原始链接，在新窗口打开。

详情加载期间，页首只以骨架占据标题与元信息行两行：骨架沿用时刻页骨架的色块、同步透明度起伏与减少动态效果规则（[时刻页骨架决策](../moment/20261005-day-outline-and-skeleton-to-card.md) D3），每一行与真实文字的行高、字号和间距相同，详情到达时标题与元信息行落在骨架所在的位置。骨架是纯前端的固定形状，不需要额外请求；正文长度无从预知，不画骨架。返回链接只依赖地址，加载期间照常显示，它绝对定位，不影响骨架位置；加载期间它指向地址中的 `path`。骨架对辅助技术隐藏，屏幕阅读器读到的是“正在加载对话…”状态。

正文是一列消息，不使用聊天气泡：每条消息上方是说话人小标签（user 为“你”，assistant 为来源名称）；正文使用内容字体，user 消息放在浅色底块中，assistant 不加底色，两者都左对齐。Markdown 展示规则不变：GFM、不执行原始 HTML、不加载远程图片、链接在新窗口打开。不再显示 Session ID、“会话存档”一类标签和页脚。

## D2：分叉写成一句文字

在每个分叉点下方显示一行小字：“此处分为 K 支：选项 · 选项 · …”。

- 每个选项以它对应 Path 的标题命名，过长时截到 14 个字符加 `…`；当前选项带 accent 色下划线。
- 一个选项可能对应一棵子树里的多条 Path：以点选它时会打开的那条（子树内更新时间最新的一条）命名；正在阅读的 Path 就在这棵子树里时，改以正在阅读的 Path 命名，当前选项与页首标题一致。
- Path 在此处的内部节点结束时，选项同样是那条 Path 的标题；选中后下方没有消息，本身就说明这一支到此为止。
- 截断后几个选项读起来相同时，每个都在后面加“ · Session ID”。新建分支默认沿用发起时所读 Path 的标题，同名分支很常见；管理分支列表也用 Session ID 区分它们。标题各不相同时不加。
- 选择一项后替换其后的全部消息，Path 选择规则与前序决策相同；地址中的 `path` 以替换历史记录的方式更新。

用标题而不用下一条消息的开头命名：标题是读者给一条分支起的名字，时间线卡片、页首和管理分支列表都用它指称 Path；消息开头还常常是寒暄（“好的”“继续”）或链接，几个选项读起来差不多，区分不了。

## D3：管理操作收进标题菜单

标题右侧的 `···` 按钮遵循 Web 导航根决策 D5，菜单项依次为：

| 菜单项 | 行为 |
| --- | --- |
| 编辑对话 | 打开编辑对话框：标题只改当前 Path，来源改整个 Conversation |
| 分支管理 | 打开分支管理弹窗，规则同前序决策 D3；新分支与更新的标题规则见标题归属决策 D2 |
| 删除对话 | 打开确认弹窗，确认后删除整个 Conversation |

界面文案统一使用“对话”，不再使用“会话”。编辑仍使用对话框而不是原位编辑，以保留一次保存只有一个成功或失败结果的约定。

## D4：删除整个对话后回到进入来源

| 进入方式 | 删除成功后 |
| --- | --- |
| 从时刻进入（地址带 `date`） | 跳到 `/?date=…`，回到原来的日期 |
| 从摘星进入 | 跳到摘星入口页；入口页确定前不会出现此情况 |
| 直接打开链接（没有 `date`） | 跳到 `/` |

跳转使用替换历史记录的方式，后退不会回到已删除对话的地址。删除失败时留在原页并显示错误，可以重试。

## D5：删除单个 Path 时删除其 Moment，阅读页展示剩余 Path

服务端在同一事务中删除该 Path、它的 Moment 以及失去引用的消息（Moment 根决策 D3）。界面上：

- 阅读页留在原 Conversation，改为展示剩余 Path 中按前序规则选出的那一条，并以替换方式更新地址中的 `path`。
- 返回链接仍然回到原来的日期；那一天的时间线上被删除 Path 的卡片已经消失。
- 只剩一个 Path 时，分支管理不提供删除 Path，最后一个 Path 通过“删除对话”删除。

## D6：编辑后的投影

编辑对话保存成功后，不刷新页面即可看到：

- 阅读页：当前 Path 的标题、元信息行中的来源、说话人标签中的来源名称和“继续对话”链接。
- 时间线：被编辑 Path 的卡片显示新标题；该 Conversation 全部 Path 的卡片显示新来源；其他 Path 的标题不变。

## 不变量

1. 阅读页展示的消息序列总是某一条真实 Path 的完整序列。
2. 元信息行的消息数与“继续对话”链接都属于当前 Path。
3. 管理操作只出现在阅读页的标题菜单中，会话收藏页不再存在。
4. 删除对话成功后，历史记录中不保留指向该对话的当前条目。
5. 删除 Path 后不留下没有详情的 Moment，阅读页也不展示已删除的 Path。
6. 编辑保存成功后，阅读页与时间线卡片上同一 Path 的标题一致，全部 Path 的来源一致。
7. 分叉句的每个选项都以一条真实 Path 的标题命名，任意两个选项读起来不同（必要时带 Session ID）。

## 为什么不是这些替代方案

| 替代方案 | 优势 | 取舍 |
| --- | --- | --- |
| 保留会话收藏页及其卡片菜单 | 改动最小 | 与“时间线优先”的产品方向冲突；对话列表接口已按 Moment 根决策移除 |
| 管理操作放在时间线卡片上 | 不用进入详情 | 卡片只回答“是什么、何时发生”；一个对话可能有多张卡片，删除对话的作用范围不直观 |
| 保留聊天气泡 | 与来源网站相似 | 左右摆动的气泡不适合回看和摘录；书页式排版与原型风格一致 |
| 保留分叉下拉选择器 | 现成组件 | 下拉框是全页最重的控件，选项藏在弹出列表里；一句文字可以直接看到各分支 |
| 选项以下一条消息的开头命名 | 直接说明分支从哪句话开始不同 | 与其他地方指称 Path 的名字不一致；开头常是寒暄或链接，区分不了 |
| 内部末端写作“在此结束” | 一眼看出这一支到此为止 | 选中后下方没有消息已说明结束；同一末端多个 Session 时还要再加 Session ID，规则多出一套 |
| 删除对话后总是回到 `/` | 规则简单 | 从某一天进入的读者会被带到今天，失去刚才浏览的位置 |
| 删除 Path 后回到时间线 | 与删除对话一致 | Conversation 仍然存在，读者多半还要继续看其他分支 |

## 本决策未解决的问题

- **摘星入口页**：从摘星进入时的地址形式与删除后的落点，待摘星根决策确定后补充。
- **消息时间**：消息本身没有时间戳，阅读页不显示每条消息的时间。
- **阅读位置**：长对话的滚动位置是否在切换 Path 或返回后恢复，暂不承诺。

## 落地与验收

`ConversationPage` 按 D1、D2 渲染页首、正文和分叉句；`ConversationMenu` 承载 D3 的三项操作与对话框；分支管理弹窗从标题菜单打开，树图沿用 React Flow，配色改用 token。删除对话按 D4 跳转，`path` 指向已删除 Path 时页面回退到默认 Path 并替换地址。会话收藏页与卡片菜单已删除，接口未因本决策改变。

组件测试覆盖不变量 1–4、6 的界面部分与 D2 的分叉选项，单元测试覆盖不变量 7 的选项命名，真实 PostgreSQL 测试覆盖不变量 5 的数据部分，Chromium 测试覆盖编辑、删除与刷新后的分叉状态。删除对话失败后的界面没有直接测试，见核心测试用例。
