# 从时刻页日期菜单导入对话，成功后打开阅读页并返回导入日期

新建对话的导入入口从会话收藏页的“导入会话”按钮移到「时刻」页日期标题旁的悬停菜单。导入表单的发生时间默认取正在浏览的那一天；导入成功后直接打开新 Path 的对话阅读页，页上的返回链接指向本次导入所选的日期，而不是导入前浏览的日期。分支导入和追加更新仍从阅读页的分支管理发起，成功后同样以本次提交的日期作为返回日期。

当前为 `approved`，已通过评审，核心测试用例见[导入入口与成功落点](../../../test-cases/server/import/import-entry.md)。继承[创建会话、创建分支和追加更新使用明确的导入目标](20260919-explicit-branch-and-append-imports.md)的三种导入操作、校验、幂等与事务语义，只修改界面入口、表单默认值和成功后的落点。涉及 `apps/palace-web` 的时刻页与导入对话框；服务端接口不变。页面地址规则见[Web 导航根决策](../../web/navigation/0-text-nav-day-routes-and-moment-opening.md)，阅读页见[对话阅读页](../conversation/20261004-reading-page-owns-conversation-actions.md)。

## 继承与修改

| 前序约定 | 本次决定 |
| --- | --- |
| 主页面导入携带标题、来源、Session ID、完整 JSON、发生时间和幂等键，创建 Conversation 及第一条 Path | 继承字段与语义；入口改为时刻页日期菜单，见 D1 |
| 分支导入和追加更新通过 Conversation ID、Path ID 定位，禁用字段不变 | 继承；从阅读页的分支管理发起。标题字段的变化见[标题从 Conversation 移到 Path](../conversation/20261005-title-belongs-to-path.md) D2：三种导入都携带 Path 标题 |
| 更新弹窗回填 Path 原 `occurred_at`，允许修改 | 继承，不变 |
| 新建导入的发生时间默认为当前时间 | 修改：默认取正在浏览的日期，见 D2 |
| 导入成功直接打开本次 Path | 继承；补充返回日期的取值，见 D3 |
| 幂等、前缀、追加限制与事务原子性 | 继承，不变 |

## D1：入口在时刻页日期标题旁

时刻页的日期标题区域有一个 `···` 按钮，显示规则遵循 Web 导航根决策 D5：鼠标在日期标题区域内才显示，触屏设备始终显示。菜单目前只有一项“导入对话”，打开导入对话框。

日期标题本身的交互不变：点击日期打开日期选择器，键盘左右键切换日期。`···` 是独立按钮，点击它不会打开日期选择器。

导入属于“在这一天放入一条记录”，因此放在日期旁，而不是导航或全局工具栏；以后其他类型的创建入口也加入同一菜单。

## D2：发生时间默认取正在浏览的日期

打开导入对话框时，发生时间的默认值为：

| 正在浏览 | 默认发生时间 |
| --- | --- |
| 今天 | 当前本地时间 |
| 其他日期 | 该日期加上当前本地时刻 |

用户可以把日期和时间改成任意值，提交的仍是用户确认的 `occurred_at`，导入时间不会伪装成发生时间。默认值只是减少在过去某天补录时的操作。

## D3：成功后打开阅读页，返回导入日期

导入成功后，以替换历史记录的方式跳到：

```text
/conversations/<conversation_id>?path=<path_id>&date=<本次 occurred_at 的本地日期>
```

- 返回链接显示并指向本次导入所选的日期，定位到新 Moment；它不是导入前浏览的日期。用户刚把这段对话放在那一天，回到那一天能立即看到它出现在时间线上。
- 使用替换历史记录，是为了让后退不回到已经关闭的导入对话框所在的状态，而是回到导入前的页面。
- 幂等重试命中已有结果时，同样按返回结果中的 Path 跳转。

分支导入和追加更新成功后，阅读页切换到本次 Path，返回日期改为本次提交的 `occurred_at` 所在日期。追加更新会把 Moment 移到新的日期（Moment 根决策 D3），返回那一天才能看到它。

## 不变量

1. 新建导入只能从时刻页的日期菜单发起，分支与更新只能从阅读页的分支管理发起。
2. 提交的 `occurred_at` 总是用户在表单中确认的值。
3. 导入成功后，阅读页展示的是本次导入的 Path。
4. 导入成功后的返回日期等于本次提交 `occurred_at` 的本地日期。
5. 导入失败不跳转，表单保留用户输入并可重试。

## 为什么不是这些替代方案

| 替代方案 | 优势 | 本次取舍 |
| --- | --- | --- |
| 导入按钮常驻在导航栏或页面右上角 | 容易发现 | 违背少放控件的原则；导入是低频操作 |
| 导入成功后回到时间线并突出新卡片 | 与移动端约定一致 | 新导入的对话最常见的下一步是确认内容是否正确，打开阅读页更直接；移动端约定不约束 PC Web |
| 返回导入前浏览的日期 | 回到出发点 | 若发生日期与浏览日期不同，回去后看不到刚导入的对话，容易误以为导入失败 |
| 默认发生时间总是当前时间 | 实现简单 | 在过去某天补录时每次都要改日期，而在那一天打开菜单本身已经表明了意图 |

## 本决策未解决的问题

- **其他 Moment 类型的创建**：菜单会加入其他类型的入口，届时由各类型的决策确定。
- **批量导入与来源网站完整导出格式**：仍不在范围内，沿用根决策。

## 落地顺序

1. **入口迁移**：时刻页日期标题旁加入菜单与“导入对话”，导入对话框按 D2 设置默认值；会话收藏页的导入按钮随该页一起移除。完成条件：不变量 1、2 有组件测试。
2. **成功落点**：按 D3 跳转并设置返回日期。完成条件：不变量 3、4 有浏览器测试，包括发生日期与浏览日期不同的情况。

服务端导入接口、校验与幂等语义在全部阶段保持不变。
