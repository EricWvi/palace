# 带空格的标签在正文里写成 `#[[词 词]]`，不用结尾 `#` 收束

正文里的标签原来是 `#` 加连续的非空白字符，带空格的标签无法表达。在新建札记中选择已有的 `Vibe Coding` 后，保存时只得到
`Vibe`，`Coding` 留在正文里。更严重的是编辑：agent 写下的 `Vibe Coding` 标签被写回正文成 `#Vibe Coding`，保存一次就被悄悄
改成 `Vibe` 加正文里多出的 `Coding`。本决策让带空格的标签写成 `#[[Vibe Coding]]`。新建札记的补全、编辑时的写回都用这种
写法，提取规则也能读回它。不带空格的标签仍是 `#rust`。

当前为 `implemented`，核心测试用例见[回响页](../../../test-cases/web/echo/echo-page.md)。本决策修改[回响页根决策](0-jotting-wall-with-daily-recall-pile.md) D6 的标签识别规则，
以及[放大卡片里编辑和删除札记](20261101-edit-and-delete-a-zoomed-jotting-with-title-slips.md) D2 的写回格式。只涉及 `apps/palace-web`；
服务端接口和文件格式不变，标签本来就可以含空格。

| 前序约定 | 本决定 |

| 根决策 D6：空白或行首之后的 `#词` 是标签；`# 标题`、`C#`、`a.html#x`、围栏代码块里的 `#` 不是 | 继承，并新增 `#[[…]]` 形式，见 D1 |
| 根决策 D6：输入 `#片段` 时补全已有标签，确认后写成 `#标签 ` | 修改：带空格的标签补全为 `#[[标签]] `，见 D1 |

## D1：`#[[…]]` 包住带空格的标签

- 空白或行首之后的 `#[[` 开始一个标签，到同一行第一个 `]]` 结束。括号内不能以空白开头或结尾，不能含 `]`；不满足时按原来的
  `#词` 规则读。`]]` 之后可以紧跟任何字符，例如 `#[[Vibe Coding]]，`。
- 补全和写回时，标签含空白就写成 `#[[标签]]`，否则写成 `#标签`。因此写回的每个标签都能原样读回，编辑后保存不会改变标签。
- 手打 `#[[新 标签]]` 也会新建带空格的标签。补全只对 `#` 后的单个词生效，输入 `#[[` 时不提示。

**为什么不用结尾 `#`（`#Vibe Coding#`）**：曾先按这种写法实现，测试随即发现 `#阅历 第三章 C# 不算` 被读成标签
`阅历 第三章 C`：`C#`、`F#` 末尾的 `#` 与结尾 `#` 无法区分。在这里写札记的人常提到这些语言，所以否决了这种写法。`#[[` 在正文里
几乎不会自然出现，`]]` 又明确标出了结尾。

## 为什么不是这些替代方案

| 方案 | 优势 | 否决理由 |
| --- | --- | --- |
| 结尾 `#` 收束（Bear） | 少打字符 | 与 `C#`、`F#` 冲突，见 D1 |
| 按已有标签做最长匹配 | 不引入新写法 | 无法新建带空格的标签；读出的结果取决于标签列表是否加载完成；`#Vibe Coding 很好玩` 有歧义 |
| 选中的标签变成独立的标签块 | 不需要任何写法 | 与「标签写在正文里」的输入方式和编辑写回冲突，界面改动最大 |

## 不变量

1. 网页写进草稿的每个标签（补全或编辑写回），按同一套提取规则读回时与原标签相同。
2. `C#`、`F#` 等以 `#` 结尾的词不会改变同一行里标签的范围。
