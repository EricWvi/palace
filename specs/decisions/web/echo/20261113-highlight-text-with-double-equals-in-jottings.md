# 札记正文用 `==文字==` 高亮

札记正文里的 `==文字==` 显示为黄色高亮，颜色与摘星页标注的黄色高亮相同。只有札记支持这个写法，文章和对话中的 `==` 仍是普通文字。

当前为 `implemented`，核心测试用例见[回响页](../../../test-cases/web/echo/echo-page.md#jotting-bodies-must-highlight-double-equals-and-nothing-else-may)。继承[回响页](0-jotting-wall-with-daily-recall-pile.md)，修改下表所列部分。

## 继承与修改

| 前序约定 | 本决定 |
| --- | --- |
| 回响页决策：卡片正文与其他页面共用同一个 Markdown 组件 | 保留共用组件；札记在共用语法之外多认 `==文字==`，见 D1 |

## D1：只在札记里生效

`==` 不是 CommonMark 或 GFM 的语法。导入的对话和文章是别人的文字，散文和没加反引号的代码里常有 `a==b and c==d`，在那里启用会把 `b and c` 标成高亮。札记是自己写的，写下 `==` 就是要强调。所以 Markdown 组件按“方言”区分：默认方言不变，札记方言只多出这一种语法。瀑布流卡片、放大卡片和卡片组都用札记方言。

## D2：成对规则

- 恰好两个 `=` 才算一个记号，`=`、`===` 及更长的都是普通文字；`\==` 是转义，行内代码里的 `==` 也不算。
- 开始的 `==` 后面不能是空白，结束的 `==` 前面不能是空白，所以 `a == b` 不会高亮。只看空白、不看标点，因为 CommonMark 的标点规则会让 `==重点。==后文` 配不成对，这与正文对 `**` 启用 CJK 友好规则的理由相同。
- 结束的 `==` 与它之前最近的开始配对，内部可以有加粗、斜体、链接等行内格式，也可以包含软换行；高亮不跨段落。没有配上的 `==` 原样显示。

## D3：外观

高亮渲染为 `<mark>`，背景用摘星页黄色高亮的同一个颜色变量，深浅色主题随之切换。与标注一样没有内边距，高亮不会让行重新排版。

## 为什么不是这些替代方案

| 方案 | 否决理由 |
| --- | --- |
| 所有页面都认 `==` | 导入的对话和文章不是为这个语法写的，`a==b` 会被误标，违反不变量 2 |
| 在文本节点上用正则替换 `==…==` | 解析后已分不清 `\==` 是不是转义；记号跨过 `**加粗**` 时落在不同的文本节点里，配不成对 |
| 沿用 CommonMark 的标点规则判断能否开合 | `==重点。==后文` 配不成对，中文里句末标点挨着记号很常见 |
| 用户可选的多种颜色（如 `==yellow:…==`） | 札记要的是一种强调，不是分类；多一种写法就多一套没有约定的语法，与摘星页标注的颜色体系也对不上 |

## 不变量

1. 札记正文里成对的 `==文字==` 显示为黄色高亮，两侧的 `==` 不显示。
2. 文章、对话等其他页面的 `==` 原样显示。
3. 不符合 D2 的 `==` 原样显示，正文文字不丢失。
