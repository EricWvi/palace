# 粘贴进札记的图片上传为 Palace 媒体，原地写成 `![文件名](/api/media/<id>)`

在新建札记的输入框和放大卡片「修订」的正文框里粘贴图片时，图片上传到 Palace 媒体，并在光标处写成 `![文件名](/api/media/<id>)`。截图（文件名为 `image.png`）和在文件管理器里复制的图片文件都算；剪贴板里没有图片时仍是普通粘贴。上传期间可以继续输入，但不能保存。

当前为 `implemented`，核心测试用例见[回响页](../../../test-cases/web/echo/echo-page.md#a-pasted-picture-must-become-palace-media-in-place)。继承[瀑布流的札记点时间放大，放大卡片加载 Palace 媒体图片](20261101-zoom-wall-jottings-by-their-time-and-load-palace-media.md)和[放大卡片里编辑和删除札记](20261101-edit-and-delete-a-zoomed-jotting-with-title-slips.md)，回答前者留下的“札记的图片上传”。只涉及 `apps/palace-web`，上传沿用已有的 `POST /api/media`，服务端接口与札记文件格式不变。

## 继承与修改

| 前序约定 | 本决定 |
| --- | --- |
| 放大决策 D4：放大卡片只加载 `/api/media/<uuid>` 的图片，缩略卡片显示占位 | 继承，不变；粘贴写出的正是这种地址 |
| 放大决策：札记的图片上传留给后续决策 | 修改：新建和修订时粘贴图片即上传，见 D1、D2 |
| 放大决策：札记中的媒体没有删除保护，引入上传时与引用关系一起决定 | 继承现状，仍不保护，理由见“本决策未解决的问题” |
| 编辑决策：有改动的草稿只能通过「取消」或保存离开 | 继承；上传中的占位也算改动 |

## D1：什么算粘贴图片

- 剪贴板里的文件中 MIME 类型为 `image/*` 的才上传；同时粘贴的文本和其他文件忽略。没有图片文件时不拦截粘贴，文字、网页内容照常粘进去。
- 多张图片各占一行，按剪贴板里的顺序。
- alt 文字是文件名；剪贴板没给文件名时写 `image.<子类型>`。文件名里的 `[`、`]`、`\` 加反斜杠转义，以免提前结束 alt。上传时文件名和类型一并交给服务端记录。

## D2：上传中的占位和保存

- 粘贴后光标处立即写入占位 `![上传中 文件名…](uploading-N)`，光标移到占位之后。占位的地址不是媒体地址，即使被看到也不会加载任何东西。
- 上传成功后占位替换为 `![文件名](/api/media/<id>)`；失败时占位删除，并提示“图片上传失败”和原因。替换时光标保持在原来的文字旁边。
- 有图片在上传时，新建框的 Ctrl/Cmd + Enter 不保存，修订的「保存」不可用，两处都显示“图片上传中…”。这样不会把占位存进札记文件。
- 修订在上传完成前被取消时，上传照常完成，但不再写回任何草稿；媒体留在存储里，没有被引用。

**为什么先写占位**：上传可能要几秒。如果等上传完成再插入，就得记住当时的光标位置，而这期间写下的字会让位置失效；占位让图片的位置跟着文字走，替换时按占位文本查找，与输入了多少字无关。

## 为什么不是这些替代方案

| 方案 | 优势 | 取舍 |
| --- | --- | --- |
| 图片转成 data URL 直接写进正文 | 不需要上传 | 札记文件变得巨大，Git 仓库膨胀；放大卡片也只放行 `/api/media/<uuid>` |
| 上传完成后才插入，期间不显示 | 正文里不出现临时文字 | 插入位置要按粘贴时的光标推算，上传期间的输入会让它错位；看不出图片在哪 |
| 上传期间禁止输入 | 不必处理光标偏移 | 一张大图要等几秒才能继续写，打断思路 |
| 加一个“插入图片”按钮或支持拖放 | 不依赖剪贴板 | 用户只要求粘贴；以文字为主的卡片不加按钮，拖放留给后续需要时再定 |

## 本决策未解决的问题

- **删除保护**：札记只在文本里引用媒体，`DELETE /api/media/<id>` 拦不住被札记引用的媒体，取消的上传也会留下未被引用的媒体。目前没有任何界面或流程删除媒体，暂不处理；以后引入媒体删除或清理时，与札记引用的解析一起决定。

## 不变量

1. 剪贴板里没有图片文件时，粘贴行为与原来相同，不发出上传请求。
2. 上传成功的图片在正文中写成 `![文件名](/api/media/<id>)`，位于粘贴时光标所在的位置。
3. 有图片在上传时，新建和修订都不会保存；保存的正文里不含占位。
4. 上传失败时占位被删除，并显示失败原因，其他文字不受影响。
