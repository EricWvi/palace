# 瀑布流卡片的时间单独占页脚最后一行，标签在它上面

瀑布流卡片的页脚分成两部分：标签在上面换行排开，时间单独在最后一行。没有标签的札记只有时间一行。点时间放大、点标签筛选的规则都不变，变的只是位置。回顾卡片组和放大卡片的页脚不变，它们的标签不能点。

当前为 `implemented`，核心测试用例见[回响页](../../../test-cases/web/echo/echo-page.md#a-wall-jotting-must-open-in-full-by-its-time-and-come-back-as-it-was)。继承[瀑布流的札记点时间放大](20261101-zoom-wall-jottings-by-their-time-and-load-palace-media.md)和[回响页](0-jotting-wall-with-daily-recall-pile.md)，修改下表所列部分。

## 继承与修改

| 前序约定 | 本决定 |
| --- | --- |
| 回响页决策：页脚是时间加标签，标签可以换行 | 修改：瀑布流卡片的标签在上，时间单独占最后一行，见 D1 |
| 放大决策 D2：页脚的时间是唯一的放大入口 | 继承，不变 |
| 回响页决策：页脚里的标签可以点击筛选 | 继承，不变 |

## D1：时间和标签分行

时间和标签原来在同一行，字号、颜色相同，间隔只有 10px。近期札记的时间是「3 小时前」这样的短词，看起来就像第一个标签，想放大时常常点成了标签。点错的代价也不对等：误开放大卡片按 Escape 就回来，误点标签则会筛选并滚回页面顶部，读到的位置就丢了。

分行之后，时间左边和下面都是卡片内边距，右边是空白，旁边没有别的可点的东西。标签单独占一行或几行，多少都排得整齐。代价是有标签的卡片多一行高，瀑布流略稀。

## 为什么不是这些替代方案

| 方案 | 优势 | 取舍 |
| --- | --- | --- |
| 时间在左、标签推到右边 | 不增加行高 | 标签多时换行后左右两块对不齐，不好看 |
| 时间移到卡片顶部 | 不增加行高，两者在卡片两头 | 卡片先看到时间而不是文字，违背“以文字为主” |
| 布局不动，只加分隔符、淡化标签、扩大时间的点击区 | 改动最小 | 两者仍然挨着，只能减少点错 |
| 点整张卡片放大 | 入口最大 | 要推翻放大决策 D2，选字与点击的区分不稳定，那里已比较过 |

## 不变量

1. 瀑布流卡片的时间单独在页脚最后一行，同一行没有标签。
2. 点时间放大、点标签筛选的行为不变。
