# 以五个文字导航组织 Web，时刻按日期寻址，Moment 按归属决定原地展开或跳转

Web 端用顶部的五个文字导航（时刻、行事、旅途、摘星、回响）取代会话收藏 POC 的左侧边栏。「时刻」是唯一可以直接进入的导航，地址中携带正在浏览的日期；其余导航暂不可点击。时间线上的 Moment 按“完整内容归属哪个导航”决定打开方式：归属其他导航的（目前只有对话）点标题跳到该导航的详情页，并能回到来时的日期和位置；只属于当天的原地展开。低频操作统一收进悬停时才出现的 `···` 菜单。

当前为 `implemented`，核心测试用例见[文字导航与时刻地址](../../../test-cases/web/navigation/text-nav-and-day-routes.md)。本文件是 `web/navigation` 的根决策，没有前序 ADR，落地了[Moment 根决策](../../server/moment/0-moment-supertype-and-typed-details.md)的第 4 步“主页面改为按天的 Moment 列表”。视觉参照为 `design/1-prototype.html` 与 `design/2.1-moment-conversation.html`。会话收藏页、左侧边栏和旧首页地址已移除，没有保留兼容；对话阅读与管理、导入入口分别见[对话阅读页](../../server/conversation/20261004-reading-page-owns-conversation-actions.md)和[导入入口](../../server/import/20261004-import-from-day-menu-and-open-reading-page.md)。

## 问题与约束

- 产品以“某一天发生了什么”为第一视角（`docs/product/产品方向.md`），会话收藏 POC 却以功能页面组织。
- 五个导航词及各自承载的内容已经确定；目前只有「时刻」的时间线和「摘星」的对话阅读页有内容。
- 详情必须能回到原来的日期和位置（`docs/product/跨端形态.md` 统一交互契约第 4 条）。
- Palace 主要由 Eric 自用，美观简洁优先于可发现性，Web 端以文字为主，少放按钮、图标和说明文案。

## D1：五个文字导航，只有「时刻」可以点击

顶部是一行纯文字导航，左侧为装饰纹样（不是 logo，不可点击）。当前页所属的导航项以 accent 色文字和下划线标示，并带 `aria-current="page"`。

| 导航 | 状态 |
| --- | --- |
| 时刻 | 可点击，进入今天的时间线 |
| 摘星 | 不可点击；对话阅读页属于摘星，打开时摘星显示为当前项 |
| 行事、旅途、回响 | 不可点击 |

不可点击的导航项照常显示文字，但不是链接：没有 `href`、悬停不出现下划线、不进入 Tab 顺序。不显示“即将推出”一类提示，也不因为没有内容而隐藏，以免导航的宽度和位置在功能陆续上线时反复变化。

「摘星」不可点击，是因为它的入口页（按 Conversation 浏览的列表）尚未设计，而原对话列表接口已按 Moment 根决策移除。目前进入摘星的途径只有从时间线打开对话，或导入成功后跳转。

## D2：「时刻」以日期寻址

| 地址 | 含义 |
| --- | --- |
| `/` | 今天的时间线 |
| `/?date=YYYY-MM-DD` | 指定日期的时间线，日期按浏览器本地时区解释 |
| `/?date=YYYY-MM-DD&moment=<moment id>` | 同上，加载后把该 Moment 滚动到视口中部，随后从地址中移除 `moment` |

- 日期标题显示为原型中的英文日期（如 `Sep 30, 2025`）；点击它打开浏览器原生日期选择器，键盘左右键前后切换一天。日期变化以替换而不是新增历史记录的方式写回 `date`：刷新和复制地址都保留当前日期，浏览器后退离开时间线而不是逐日回退。
- `moment` 只用于一次性定位，不用 URL 片段（`#id`）：片段定位会让浏览器把焦点放到该 Moment 的标题链接上并画出焦点框。滚动定位不改变焦点。
- `date` 无法解析（包括不存在的日期，如 2 月 30 日）时按今天处理，不报错。

## D3：对话阅读页的地址与来源

对话阅读页的地址是 `/conversations/:id`：

| 参数 | 含义 |
| --- | --- |
| `path` | 当前展示的 Path ID；缺省或已不存在时按[Path 选择规则](../../server/conversation/20260919-conversation-tree-and-session-paths.md)选择，并替换回地址 |
| `date` | 读者来自「时刻」的哪一天；存在时页面显示返回链接 |

`date` 同时承担“进入来源”的含义：有 `date` 表示从时刻进入，返回和删除后的落点都是 `/?date=…`；没有 `date` 表示从摘星或直接链接进入，落点是摘星（入口页确定前退回 `/`）。

返回链接是标题上方一行很淡的文字「← M 月 D 日」，指向 `/?date=…&moment=<当前 Path ID>`。它悬在标题上方的留白里，标题与时刻页的日期标题处在相同高度，切换页面时不跳动。浏览器后退与返回链接到达同一处。页面内切换 Path 只替换历史记录中的 `path`。

## D4：Moment 的打开方式由内容归属决定

| Moment 的完整内容 | 点击标题 | 当前类型 |
| --- | --- | --- |
| 归属其他导航 | 跳到该导航的详情页，并按 D3 携带来源日期 | 对话（摘星） |
| 只属于当天 | 在时间线上原地展开，再次点击收起 | 睡眠、歌曲等（尚未实现） |

时间线卡片只回答“这是什么、什么时候发生”，展示类型、标题和少量摘要（对话的卡片字段见[对话 Moment 卡片字段](../../server/moment/20261004-conversation-moment-card-fields.md)）。跳转型 Moment 不在时间线上提供折叠详情，避免同一份内容出现两种完整视图。以后新增 Moment 类型时，先按这张表判断其归属；照片在相册中组织时归旅途，即为跳转型。

## D5：低频操作收进悬停菜单

一块区域的低频操作放在该区域旁的 `···` 按钮后面：

- 鼠标在该区域内时显示 `···`，离开后隐藏；键盘聚焦到按钮或菜单打开时保持显示；不支持悬停的触屏设备始终显示。
- 点击 `···` 在按钮下方弹出菜单；选择一项、点击菜单外或按 Esc 关闭，按 Esc 后焦点回到按钮。
- 破坏性操作排在菜单最后。

目前有两处：时刻页的日期标题区域（导入对话）和对话阅读页的标题区域（编辑、分支管理、删除）。

## 不变量

1. 任一时刻，导航中至多一项带 `aria-current="page"`，且它是当前页面所属的导航。
2. 不可点击的导航项不是链接，也不进入 Tab 顺序。
3. 时间线页面的地址总是包含可以还原当前日期的信息；刷新后看到同一天。
4. 从时间线进入对话阅读页后，返回链接与浏览器后退都回到进入前的日期。
5. 回到时间线时，焦点不落在任何 Moment 的标题上。
6. 同一 Moment 类型只有一种打开方式。

## 为什么不是这些替代方案

| 替代方案 | 优势 | 取舍 |
| --- | --- | --- |
| 隐藏尚无内容的导航项 | 不出现点不动的字 | 导航宽度和位置会随功能上线反复变化；五个词本身是产品结构的说明 |
| 摘星进入现成的对话列表 | 立即有入口 | 列表接口已按 Moment 根决策移除，入口页也尚未设计 |
| 对话在时间线上原地展开 | 不离开当天 | 长对话会把当天其他 Moment 挤得很远；对话的完整视图归属摘星 |
| 日期放在路径中（`/days/2025-09-30`） | 地址更像资源 | 首页就是时间线，`/` 与 `/?date=` 共用一个路由更简单；日期是浏览状态而不是资源身份 |
| 用 `#moment-id` 回到原位置 | 浏览器原生支持 | 浏览器会聚焦目标链接并画出焦点框，回到时间线时看起来像被选中 |
| 日期切换新增历史记录 | 后退可以逐日回看 | 键盘逐日浏览会堆积大量历史，后退无法离开时间线 |
| 管理操作常驻显示 | 可发现性好 | 违背以文字为主、少放控件的原则；这些操作使用频率低 |

## 本决策未解决的问题

- **摘星入口页**：按 Conversation 浏览的列表、搜索与筛选，由摘星的根决策决定。
- **行事、旅途、回响**：各自的内容与入口在对应功能出现时决定。
- **Moment 时间的展示位置**：时间线上暂不显示时间。
- **移动端**：移动端会另行设计，本决策只约束 PC Web；手机宽度下只保证不溢出。

## 落地与验收

`apps/palace-web` 的应用框架改为单栏页面：`PalaceHeader` 渲染纹样与五个导航，`TimelinePage` 承担 `/` 及其 `date`、`moment` 参数，`ConversationPage` 承担 `/conversations/:id`；`MoreMenu` 以 Radix 下拉菜单实现 D5。会话收藏页、左侧边栏和对话列表接口已删除。

组件测试覆盖不变量 1–3、5、6 与菜单的键盘行为，Chromium 测试覆盖返回链接与浏览器后退、悬停与触屏下的菜单显示，以及标题与日期标题等高。仍缺直接证据的部分见核心测试用例。
