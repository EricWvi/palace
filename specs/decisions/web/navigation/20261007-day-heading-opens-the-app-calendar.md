# 时刻页日期标题打开与导入表单相同的日历，不再用浏览器原生日期选择器

点击时刻页的日期标题，在标题下方弹出与导入表单“发生日期”相同的日历：中文星期与月份、年月下拉、1900–2100 年范围，打开时停在正在浏览的那一天并标为选中。选择一天后日历关闭，按原有规则以替换历史记录的方式写回 `?date=`。原来藏在标题下的原生 `<input type="date">` 移除。

当前为 `implemented`，核心测试用例见[文字导航与时刻地址](../../../test-cases/web/navigation/text-nav-and-day-routes.md#day-timeline-address-must-restore-the-viewed-day)。继承[Web 导航根决策](0-text-nav-day-routes-and-moment-opening.md)的全部地址规则，只修改 D2 中“点击日期标题打开浏览器原生日期选择器”这一项。原型 `design/1-prototype.html` 仍使用原生选择器，不随本决定修改。

## 继承与修改

| 前序约定 | 本决定 |
| --- | --- |
| 点击日期标题打开浏览器原生日期选择器（根决策 D2） | 修改：打开与导入表单相同的日历，见 D1 |
| 日期变化以替换历史记录的方式写回 `date`，刷新与复制地址保留当天 | 继承，不变 |
| 键盘左右键前后切换一天 | 继承；日历打开时方向键在日历内移动，不切换时间线 |
| 无法解析的 `date` 按今天处理 | 继承，不变 |

## D1：日期标题与导入表单共用一个日历

- 两处使用同一个日历组件，外观与交互完全一致；导入表单另外保留时分输入，日期标题只选日期。
- 日历出现在标题下方左对齐的浮层中，打开时显示正在浏览的那一天所在的月份。
- 用指针选择后焦点不留在日期标题上；用键盘打开的，关闭后焦点回到标题。原因与“时刻”导航相同：焦点留在标题上时，随后按左右键切换日期会让浏览器给它画出焦点框。
- 日历代码首次指向或聚焦日期标题时才加载，大多数访问不会打开它。

为什么不再用原生选择器：同一个应用里选日期出现两种外观，原生选择器的样式随浏览器和系统变化，无法与设计系统一致；它也只能挂在一个隐藏的输入框上，由 `showPicker()` 打开，不支持该 API 的浏览器上点击标题没有反应。

## 不变量

1. 日期标题与导入表单的“发生日期”使用同一个日历组件。
2. 从日历选择一天后，地址以替换历史记录的方式变为该日期，日历关闭。
3. 日历打开时，方向键不切换时间线的日期。

## 为什么不是这些替代方案

| 替代方案 | 优势 | 取舍 |
| --- | --- | --- |
| 保留原生选择器 | 无需加载日历代码，移动端是系统控件 | 与导入表单的日历外观不同，样式不受设计系统控制，依赖 `showPicker()` |
| 导入表单也改用原生选择器 | 两处一致且更轻 | 原生日期输入的外观在各浏览器差异大，导入表单已按设计系统做了日历 |

## 落地与验收

`DayCalendar` 封装共用的日历配置，`DateTimePicker` 与 `TimelinePage` 都使用它；时间线以懒加载引入。组件测试覆盖日历的年月下拉、打开时选中当天、日历内方向键不切换日期，以及选择后以替换方式写回地址。
