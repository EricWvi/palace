# 文章正文与对话消息可以标注：四色高亮、划线、波浪线和页边批注，锚定在渲染后的文字上，「只看标注」折叠其余段落

摘星的文章导入后正文不再改变，对话只会追加消息，已有消息同样不变，所以两者都可以按字符位置长期锚定标注。读者选中文字后，选区上方浮出一个小条：四种高亮颜色、划线、波浪线和「批注」。一处标注由锚点、可选的样式、可选的一段批注组成，二者至少有一个。宽屏上批注放在正文右侧的页边栏，与原文对齐；页面只在有批注时才加宽，加宽方式与回响页相同。窄屏上批注以浮层显示在原文下方。原文与批注在鼠标悬停时互相点亮。标题旁 `···` 菜单里的「只看标注」（快捷键 `a`）把没有标注的段落折叠成一行「省略 N 段」。交互定稿见原型 [`design/3.3-stars-annotation.html`](../../../../design/3.3-stars-annotation.html) 的变体 A。

当前为 `implemented`，核心测试用例见[摘星标注](../../../test-cases/web/stars/annotations.md)，接口与用法见[标注功能文档](../../../../docs/features/annotations/README.md)。本决策基于[文章通过 API 连同媒体一次导入](20261020-articles-imported-with-media.md)，同时用到对话阅读页的约定（[阅读页承担对话操作](../../server/conversation/20261004-reading-page-owns-conversation-actions.md)、[共享 Markdown 展示](../../server/conversation/20261010-shared-markdown-content-with-code-highlighting.md)）。涉及 `palace-db` 的新表与迁移、`palace-domain` 的标注校验、`palace-backend` 的标注接口与 OpenAPI、`apps/palace-web` 的 `MarkdownContent`、文章页、对话页与它们的菜单。笔记、标注的同步、跨文章汇总都不在范围内。

## 问题与约束

- 文章和对话是值得反复回看的内容。回看时，读者需要知道当时哪句话让自己停下来、当时怎么想的。
- 标注要长期指向同一段文字。文章正文导入后由触发器禁止修改（文章决策不变量 4）；对话消息的内容和结构都不会改写，删除 Path 时只会删掉不再被任何 Path 引用的消息。笔记是 Palace 之外维护、随时可能被改写的 Markdown，锚点会悄悄失效，因此不在范围内。
- Palace 主要由 Eric 自用，界面遵循「少 UI、以文字为主」：标注入口在选区上，不在页面上常驻按钮。
- 选区发生在浏览器渲染出的文字上，而不是 Markdown 源码上：读者看到的是去掉语法符号、经过代码高亮的结果。

## D1：范围

- 可以标注的是**文章正文**和**对话的每一条消息**。文章正文开头被提升为页面标题的一级标题、页首的元信息、对话里说话人的标签都不能标注。
- 一处标注只落在一个范围里：文章的整篇正文，或者一条消息。跨越两条消息的选区不弹出标注小条。
- 同一条消息被多个 Path 共用时，它上面的标注在每个 Path 里都显示：标注属于消息，不属于 Path。
- 笔记不能标注，理由见「问题与约束」。

## D2：一处标注的组成

| 部分 | 规则 |
| --- | --- |
| 锚点 | 范围内的起止位置和被选中的原文，见 D3；创建后不可修改 |
| 样式 | `yellow`、`green`、`blue`、`rose` 四种高亮，`underline`（划线）、`wavy`（波浪线），或没有 |
| 批注 | 纯文本，去除首尾空白后非空，UTF-8 不超过 16 KiB；或没有 |

- 样式和批注至少有一个。没有样式、只有批注的标注显示为「批注样式」：淡淡的强调色底，加一条强调色细线，与四种高亮区分开。有样式又有批注时，标记末尾加一个强调色小圆点。
- 修改样式或批注时，原子地替换这两项；两项都清空，等于删除这处标注。
- 四种颜色只表示读者自己的约定，系统不赋予含义：颜色超过四种以后，回看时得先回忆每种颜色代表什么。

**为什么样式和批注是一处标注的两个可选部分，而不是两种东西**：读者经常先高亮、读完一段后再回来补一句批注。如果批注是另一种标注，同一段文字上就会叠两处标注，删高亮时还得另删批注。

## D3：锚点按渲染后的文字定位，附带原文校验

一处标注的锚点是 `{ start, end, quote }`。坐标系是范围内的**标注文字**：`MarkdownContent` 渲染出的全部文本节点，按文档顺序首尾相接；文章取去掉开头标题后的正文。

- 表格结构元素（`table`、`thead`、`tbody`、`tfoot`、`tr`）直接包含的纯空白文本节点不计入，因为 React 渲染时会丢掉它们；界面自己附加的文字（代码块的「复制」按钮及其状态、图片占位「[图片：…]」）不计入，它们带有 `data-annotation-skip` 标记。
- `start`、`end` 以 UTF-16 码元计数，即浏览器字符串下标；`0 ≤ start < end`。
- `quote` 是 `[start, end)` 这一段文字，非空白，UTF-8 不超过 16 KiB。服务端校验它的 UTF-16 长度等于 `end - start`。
- 选区两端的空白去掉以后才记下锚点。

展示时，先看标注文字中 `[start, end)` 是否等于 `quote`：

1. 相等，就画在原处。
2. 不相等，就在标注文字中找 `quote` 的全部出现位置，画在离 `start` 最近的一处。
3. 一处也找不到，这处标注就不画；它仍然保存，仍计入「N 处标注」。

**为什么用渲染后的文字，而不是 Markdown 源码的偏移**：选区只存在于渲染后的 DOM 里。要把它映射回源码，必须追踪转义、实体、链接语法、高亮插入的 span 和 GFM 扩展的源码位置，而这条映射链上任何一处变化都会让源码偏移出错。渲染后的文字恰好是读者看到、选中的东西。它的代价是坐标依赖渲染器：例如「开头一级标题提升为页面标题」的规则改变时，全部偏移都会平移。`quote` 正是为了这种情况，让标注重新找到自己的文字。

**为什么最近的一处而不是第一处**：同一句话在文章里出现多次时，偏移只是被渲染变化平移了一点，离原位置最近的那处最可能是原来那处。

## D4：存储

新表 `annotation`：

| 列 | 说明 |
| --- | --- |
| `id` | UUIDv7，同时表示创建顺序 |
| `owner_id` | 标注对象的 Owner |
| `article_id` / `conversation_id` + `message_id` | 二者恰好有一组非空；分别以 `(owner_id, article_id)`、`(owner_id, conversation_id, message_id)` 复合外键引用文章与消息，`ON DELETE CASCADE` |
| `start_offset`、`end_offset`、`quote` | 锚点；由触发器禁止修改，Owner 与标注对象同样不可修改 |
| `style` | 可空，检查约束限定为 D2 的六个值 |
| `note` | 可空 |
| `created_at`、`updated_at` | 数据库时钟，毫秒精度 |

- 检查约束保证 `style` 与 `note` 至少一个非空，`start_offset < end_offset`。
- 级联删除让标注与它标注的文字同生共死：删除文章、删除对话、删除 Path 清理消息时，标注在同一事务里一起消失。
- 标注不进入同步域，不分配 `serverVersion`，与文章相同。

**为什么一张表两组外键，而不是文章、消息各一张表**：两类标注的字段、校验与接口形状完全相同，只是标注对象不同。用一张表加「恰好一组非空」的检查约束，数据库同样能排除不合法的组合；领域层再用枚举 `AnnotationTarget::{Article, Message}` 表达。

## D5：接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/articles/{id}/annotations` | 文章的全部标注 |
| `POST /api/articles/{id}/annotations` | 在文章正文上新建 |
| `GET /api/conversations/{id}/annotations` | 对话所有消息上的全部标注，不论属于哪个 Path |
| `POST /api/conversations/{id}/annotations` | 在对话的一条消息上新建，请求体带 `message_id` |
| `PUT /api/annotations/{id}` | 替换 `style` 与 `note` |
| `DELETE /api/annotations/{id}` | 删除 |

- 新建请求体：`{ message_id?, start, end, quote, style, note }`，`message_id` 只出现在对话接口里，成功返回 `201` 与标注。修改请求体：`{ style, note }`，返回 `200`。两者都为 `null` 时返回 `400`；要去掉整处标注，就用 `DELETE`。
- 标注的响应形状：`{ id, message_id, start, end, quote, style, note, created_at, updated_at }`。文章标注的 `message_id` 为 `null`，时间是 epoch 毫秒。列表是 `{ items }`，按 `id` 升序，也就是创建顺序。
- 标注对象或标注本身不属于当前 Owner 时返回 `404`，与不存在相同。`message_id` 不属于路径中的对话时同样返回 `404`。
- 列表没有分页：一篇文章或一个对话上的标注是读者亲手留下的，数量有限。

## D6：阅读页上的标注

- **创建**：在一个范围内选中文字，选区上方浮出小条，依次是四个色点、划线「文」、波浪线「文」、「批注」。快捷键是 `1`–`4`（`h` 等于黄色）、`u` 划线、`w` 波浪线、`c` 批注，只在小条显示时有效。选择样式后立刻保存并清除选区；「批注」会建一处只有批注的标注，并打开它的输入框。
- **修改**：点击标记，弹出同一个小条，当前样式带选中态，另有「改批注」（或「批注」）和「删除」。再点一次当前样式会去掉样式，如果这处标注没有批注，就整处删除。`Delete`/`Backspace` 删除整处标注，`Esc` 关闭小条。
- **标注压过 Markdown**：标记的样式优先于原有样式。行内代码、粗体、链接整体落在标注里时，它们的底色和文字颜色让给标注；引用块中的标注文字恢复正文颜色。标记不加内边距，标注前后文字不会重新换行。多处标注重叠时，先建的在外层，后建的在内层并显示在上面。
- **页边批注栏**：窗口宽度至少 1180px、且本页至少有一处带批注的标注时，正文栏保持 712px，右侧留 56px 间距和 248px 宽的批注栏。页面连同页头以 `max-width 400ms ease-out` 加宽，批注卡片等页面展开后淡入；最后一条批注删除后，页面收回到 760px 居中。只有高亮或划线的页面不加宽。卡片与原文第一行对齐，重叠时依次下推；正在编辑或刚点开的那张对齐原文，上面的卡片向上让位。
- **浮层批注**：窗口不足 1180px 时，悬停带批注的标记约 180ms，批注卡片浮现在原文下方；鼠标移入卡片时卡片保持，点击卡片即可编辑。
- **互相点亮**：悬停带批注的标记时，它的全部片段加深，对应的卡片阴影加重、文字变深，并向原文靠近 4px；悬停卡片时，原文同样点亮。卡片左缘是一条细线，颜色取自它的标注样式。
- **编辑批注**：在卡片上原地编辑。失去焦点、`Esc` 或 `⌘/Ctrl+Enter` 时保存，保存前去掉首尾空白。内容清空后，有样式的标注只去掉批注，只有批注的标注整处删除。新建的只有批注的标注在写下文字之前不保存，只在页面上占位。
- 保存失败时，标注保持保存前的状态，页面底部用一行提示说明失败原因。

## D7：只看标注

- **入口**：`···` 菜单的第一项「只看标注」，快捷键 `a`。进入后菜单项和 meta 行末尾都变为「显示全文」，`a` 和 `Esc` 也能退出。本页没有标注时菜单项不可用，`a` 不起作用。
- **meta 行**：平时在末尾显示「N 处标注」（N 为 0 时不显示），只看标注时显示「只看 N 处标注 · 显示全文」。
- **文章折叠**：正文的顶层块里，不含任何标记的块被折叠；连续的折叠块合并成一行「⋯ 省略 N 段」，点击后单独展开这一串。列表的标记在某几项里时，列表本身保留，其中没有标记的项按「省略 N 项」折叠。小节标题在它到下一个同级或更高级标题之间还有保留的块时保留，否则一起折叠。
- **对话折叠**：没有标注的消息按「省略 N 条消息」折叠；保留下来的消息内部按文章的规则折叠。分支切换行在只看标注时不显示，否则它们会悬在折叠行之间。
- **突出标注**：保留下来的段落文字变浅，只有标记中的文字保持正文颜色；标题保持正文颜色。
- **位置不变**：进入或退出时，屏幕上第一处标记保持在原来的视口位置。退出时，所有单独展开的记录都被丢弃。

**为什么折叠到段落，而不是只留下被标注的句子**：只留句子会切断上下文，回看时常常读不懂自己当时为什么划这句；保留整段并淡化其余文字，既能一眼看到标注，又能顺着上下文读。

## D8：标记由 `MarkdownContent` 在语法树上绘制

- `MarkdownContent` 接受可选的标注绘制参数，由一个排在代码高亮之后的 rehype 插件完成：按 D3 的规则计数 hast 文本节点，解析锚点，再把覆盖到的文本切开并包进 `<mark class="anno" data-annotation="<id>">`。若一个行内元素（`code`、`a`、`strong`、`em`、`del`）的全部文字都在标注里，`mark` 包在这个元素外面，让元素自己的底色被标注覆盖。相邻的片段合并成一个 `mark`，跨行内代码的标注不会出现接缝。
- 「只看标注」的折叠也在同一个插件里完成：被折叠的块加上 `folded` 类，前面插入带 `data-annotation-skip` 的折叠行，所以折叠时的标注坐标与平时相同。
- 选区换算成锚点时，在 DOM 上按同一规则计数，跳过 `data-annotation-skip` 子树。插件不切开它不计数的文本节点，所以绘制前后的坐标相同。
- 悬停点亮通过 class 切换完成，不重新渲染 Markdown。

**为什么在语法树上绘制，而不是渲染后改 DOM**：React 拥有 `MarkdownContent` 渲染出的 DOM。直接切分它的文本节点、插入元素，会在 React 下次更新或卸载时删错节点。在 hast 上绘制让标记成为 React 渲染结果的一部分，而绘制规则是可以单独测试的纯函数。

## 不变量

1. 标注只在所属 Owner 的认证上下文中可见、可改；跨 Owner 与不存在都返回 404。
2. 每处标注恰好标注一篇文章的正文或一条消息，且与标注对象属于同一 Owner。
3. 每处标注至少有样式或批注之一；锚点创建后不再改变。
4. 标注对象被删除时，它上面的标注在同一事务中删除；没有指向不存在文字的标注。
5. 锚点的 `quote` 与 `[start, end)` 的长度一致；展示时，标记只画在与 `quote` 完全相同的文字上，找不到就不画。
6. 绘制标注和折叠段落都不改变标注文字的坐标：同一段选区在任何状态下换算出的锚点相同。
7. 页边批注栏只在至少有一处带批注的标注、且窗口足够宽时出现；没有批注时，阅读页的宽度与其他阅读页相同。

## 为什么不是这些替代方案

| 替代方案 | 优势 | 取舍 |
| --- | --- | --- |
| 锚定 Markdown 源码偏移 | 不依赖渲染器 | 选区到源码的映射要穿过转义、实体、链接语法和高亮 span，任何一处出错都会悄悄标错；用渲染文字加 `quote` 校验更稳 |
| 只存 `quote`，展示时全文查找 | 没有偏移，渲染变化也不怕 | 同一句话出现多次时无法确定是哪一处 |
| W3C Web Annotation 的前后文选择器（prefix/suffix） | 定位更精确 | 正文本来不变，偏移加 `quote` 已经足够；前后文多出两列需要维护的数据 |
| 标注笔记 | 范围更大 | 笔记在 Palace 之外被改写，锚点会失效，还要设计孤立批注的展示 |
| 批注作为另一种标注，与高亮分开 | 模型更扁平 | 同一段文字上叠两处标注，删高亮时要另删批注，见 D2 |
| 文章和消息各一张表 | 外键更直接 | 字段、校验、接口完全重复；一张表加检查约束同样能排除非法组合 |
| 渲染后直接修改 DOM 画标记 | 不用改 `MarkdownContent` | 与 React 争夺 DOM，见 D8 |
| 页边批注栏常驻 | 页面宽度稳定 | 没有批注的文章也被推离中心，与其他阅读页不一致 |
| 只用浮层显示批注 | 不改页宽 | 批注平时看不见，回看时要逐个悬停；宽屏上浪费两侧的空白 |
| 只看标注时只留被标注的句子 | 最紧凑 | 切断上下文，见 D7 |

## 风险与为什么不能直接改写

- **渲染规则变化**：改变 `MarkdownContent` 的文字输出（例如开头标题的提升规则、图片占位的文字、新的 GFM 扩展），会平移已有锚点。D3 用 `quote` 兜底；如果某次改动会让大量 `quote` 失配，需要单独写迁移，按新规则重算偏移，不能只改渲染器。
- **找不到的标注**：渲染规则或 `quote` 都无法定位时，标注不显示但仍然保存。目前没有界面能列出这些标注，只能直接查表。
- **级联删除**：删除文章或 Path 会连带删掉上面的批注，而批注是读者自己写的文字。删除弹窗不单独提醒这一点，与「删除文章连同图片、视频一起删除」的既有提示一致。

## 本决策未解决的问题

- **跨文章汇总回看**：把所有标注集中按时间或来源浏览，涉及摘星的信息架构，另行决定。
- **笔记的标注**：需要先决定笔记被外部改写后，标注如何失效、如何显示。
- **标注的同步与移动端展示**：标注暂不进入同步域。
- **搜索批注内容**：摘星搜索暂不匹配批注。

## 落地与验收

- 迁移 `0018_annotations.sql` 新建 `annotation` 表、两组复合外键与检查约束，并用触发器禁止修改锚点、标注对象和 Owner。
- `palace-domain` 的 `AnnotationAnchor`、`AnnotationContent`（样式与批注至少有一个，由枚举表达）、`AnnotationTarget` 负责校验；`palace-db` 在 Owner Scope 内读写，新建时直接从标注对象的行选取，别人的对象或别的对话里的消息写不进任何行。
- `palace-backend` 提供 D5 的六个接口并写入 OpenAPI 合同。
- `apps/palace-web`：`lib/annotation-paint.ts` 是绘制与折叠的 rehype 插件，`lib/annotation-dom.ts` 按同一规则把选区换算成锚点，`components/annotation-layer.tsx` 管数据与状态，`components/annotated-area.tsx` 管小条、页边栏、浮层与快捷键，样式在 `annotations.css`。

证据见核心测试用例：领域单元测试覆盖字段校验；真实 PostgreSQL 覆盖 Owner 隔离、标注对象约束、锚点不可变和级联删除；真实 Router 覆盖接口形状与 OpenAPI 合同；jsdom 中的真实 `MarkdownContent` 覆盖坐标一致、绘制与折叠，组件测试覆盖交互，真实 Chromium 覆盖页边栏的加宽、卡片对齐与窄屏浮层。

文章与对话已有的阅读、编辑和删除行为保持不变，只是删除时连带删除标注。
