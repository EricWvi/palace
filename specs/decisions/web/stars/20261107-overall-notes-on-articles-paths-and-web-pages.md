# 总批：文章、对话 Path 和原网页各有一块全局文本，用固定在视口里的卡片展示

批注属于一段文字，读的时候冒出来的整体想法却没有地方放。本决策增加**总批**：一篇文章、一条对话 Path、一个原网页各有一块全局文本，用同一张固定在视口里的卡片书写和阅读。卡片不进入文档流，标题和 meta 行保持原样。原网页的总批在绑定文章时并入文章。

当前为 `implemented`，核心测试用例见[总批](../../../test-cases/web/stars/overall-notes.md)，交互原型见 [`design/3.4-stars-overall-note.html`](../../../../design/3.4-stars-overall-note.html)（变体 A）。本决策基于[文章与消息上的标注](20261021-annotations-on-articles-and-messages.md)、[浏览器插件在原网页上标注](../../extension/0-web-page-annotations-bound-and-migrated-into-articles.md)和[标注默认关闭](../../extension/20261021-annotating-off-until-turned-on-per-tab.md)，修改下表所列部分，其余继承。

## 问题与约束

- 想法要能随时记下：一篇长文或长对话读到中途，不应该为了写一句话离开当前位置。
- 读者不希望把这块文本放在标题下方，它会把正文往下推，而且每次打开都要先看过它。
- Palace 的界面优先简洁，低频入口靠快捷键，不加提示和占位入口。
- 原网页上的想法要跟着文章走，否则导入后就丢了。
- 灵感写下后不能丢。这与标注不同：一处标注是一次操作，失败了读者看得见；总批是连续输入，断网或两处同时写时丢的是一段文字。

## 继承与修改

| 前序约定 | 本决定 |
| --- | --- |
| 标注决策：标注属于文章正文或一条消息上的一段文字 | 不适用：总批属于整个文档，没有锚点，见 D1 |
| 标注决策：笔记不能标注 | 继承：笔记也没有总批，见 D1 |
| 标注决策：删除文章、对话或 Path 时，上面的标注一起删除 | 继承，总批同样随文档删除，见 D3 |
| 标注决策：页边栏只在至少 1180px 宽且有批注时出现，页面随之加宽 | 修改：有总批或正在写总批时也加宽，见 D5 |
| 插件决策：绑定后原网页只读显示文章的标注 | 不适用于总批：绑定后插件的卡片直接读写文章的总批，见 D7 |
| 插件决策不变量 8：未绑定的网页至少有一处原网页标注 | 修改：至少有一处原网页标注或一块总批，见 D3 |
| 插件决策 D7：插件不在本地保存数据，每次操作直接写服务端 | 修改：总批未保存成功的草稿留在本机，见 D6 |
| 标注默认关闭决策：只有在弹窗里开启后，标签页才开始工作 | 修改：总批的快捷键也算开启这个标签页，见 D6 |

## D1：范围

总批是一块 Markdown 文本，属于一篇文章、一条对话 Path 或一个未绑定的原网页，每个文档至多一块，不超过 64 KiB。

- 对话的总批挂在 **Path** 上，不挂在 Conversation 上：一条 Path 对应一个来源 Session，是读者实际读的那一支。切换分支时卡片跟着换。
- **笔记没有总批**。
- 文章导出不带总批，与标注一致，见[导出文章决策](20261107-export-article-as-upload-directory.md)。
- 总批不进入搜索、时间线、回顾和同步接口。meta 行的「N 处标注」不计总批，「只看标注」下卡片不变。

**为什么叫总批**：评点传统里，写在字句旁的是旁批，就全篇而发的是总批。

## D2：内容

存读者写下的原文，阅读时按 Markdown 渲染，图片按文档自己的规则处理。清空等于删除：不保存空白的总批。

## D3：存储

新表 `overall_note`，与 `annotation` 相同，用互斥的外键指向恰好一个目标：

| 目标 | 外键 | 删除 |
| --- | --- | --- |
| 文章 | `(owner_id, article_id)` | 随文章级联 |
| Path | `(owner_id, conversation_id, path_id)` | 随 Path 级联，删除对话时也一样 |
| 原网页 | `(owner_id, page_id)` | 随网页级联 |

每个目标至多一行，由部分唯一索引保证。`version` 每次写入都从一个数据库序列重新取值，没有总批时读作 `0`：清空会删除行，如果版本从 1 重新数起，清空再重写后可能回到某个旧值，过期的页面就能绕过 D4 的冲突检查。时间列都到毫秒。

只有总批、没有标注的未绑定网页是合法的，所以插件决策不变量 8 的约束触发器改为“至少有一处原网页标注或一块总批”。网页最后一处标注和总批都被删除时，网页记录一起删除。

## D4：接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/articles/{id}/overall-note` | 返回 `{ text, version }`；没有时 `text` 为 `null`，`version` 为 `0` |
| `PUT /api/articles/{id}/overall-note` | `{ text, version }`，`version` 是读者看到的版本，返回新版本；`text` 为空白时删除 |
| `GET`、`PUT /api/conversations/{id}/paths/{path_id}/overall-note` | 同上 |
| `GET /api/web-pages/lookup?url=` | 响应增加 `overall_note`，已绑定时取文章的总批 |
| `PUT /api/web-pages/overall-note` | `{ url, title, text, version }`，网页不存在时一并创建；已绑定返回 409 `web_page_bound` |

`version` 与当前版本不同时返回 409 `overall_note_changed`，不写入。

**为什么带版本，而标注不带**：插件决策里标注“后写入者为准”，覆盖的是一处标记；总批是一段持续增长的文字，两个标签页同时开着时，后写入者会抹掉前者的整段内容。

## D5：Palace 阅读页

卡片固定在视口内，宽 248px，右缘与批注栏对齐，底部距视口 28px，叠在批注卡片之上。批注随正文滚动时从它下面经过。

| 状态 | 表现 |
| --- | --- |
| 没有总批 | 什么都不显示，`n` 打开 |
| 有总批，收起 | 一行：「总批」和第一行文字，超出部分省略 |
| 书写或阅读 | 展开，高度随内容增长，上限 40vh |

- 点击收起的一行展开阅读，显示渲染后的 Markdown；再点击正文进入编辑。`n` 直接进入编辑，光标在末尾。书写时离开、`Esc` 或 `⌘/Ctrl+Enter` 收起，阅读时点别处或 `Esc` 收起。评审稿写的是点击即进入编辑，这样 D2 的渲染就没有机会出现，所以实现时把阅读单独分出来。
- 边写边保存：停止输入约 800ms 后保存一次，收起时再保存一次。保存失败或版本冲突时卡片保持展开、保留输入并提示，不自动合并。
- 窗口窄于 1180px 时没有批注栏，收起的卡片缩成只有「总批」二字的小标签，停在右下角，不显示第一行：这个宽度下右侧没有留白，第一行会压住正文最后几行。展开时卡片宽 300px，浮在正文上。
- 有总批或正在书写时，页面像有批注时一样加宽，所以正文的折行不随总批变化。
- `n` 在选区小条显示时、输入框里不生效。

**为什么放在批注栏底部**：它和批注是同一类东西，放在一起不需要解释；固定在视口里才能做到随时可写。收起时只占一行，不影响阅读。

## D6：插件

标签页开启标注后，右下角显示同一张卡片，宽 300px，放在现有的 closed shadow root 里，不动网页 DOM。与 Palace 的区别：

- 空的时候也显示一行「总批」：插件就是用来随手记的。
- 用 `chrome.commands` 注册快捷键，默认 `Alt+Shift+N`，不用裸的 `n`：网站有自己的快捷键，而且要在网页的输入框里也能用。读者可以在浏览器的快捷键设置里修改。
- 只有纯文本编辑，不渲染 Markdown：内容脚本运行在每个网页里，不值得为此带上渲染器。
- 在未开启的标签页上按这个快捷键，等于开启这个标签页并展开卡片。这是读者明确的操作，符合“默认不打扰”的本意。
- 未保存成功的文字按网址存进 `chrome.storage.local`，连同它所基于的版本，保存成功后删除。下次打开这个网页时，草稿优先于服务端内容，并提示还没保存；保存时仍用原来的版本，所以别处的修改不会被它覆盖。这是插件第一次在本地保存读者内容，只限尚未写入 Palace 的文字。
- 内容脚本按网页地址保存，由 service worker 判断写到网页还是绑定的文章，内容脚本不能指定文章。

Palace 自己的页面不显示插件的卡片，那里用 D5。

## D7：绑定

绑定网页时，在 `PUT /api/web-pages/binding` 的事务里把网页的总批并入文章，并删除网页上的这一行。总批没有锚点，不需要像标注那样等文章页渲染后再定位。

- 文章没有总批：直接移入。
- 文章已有总批：追加在后面，用一行 `---` 隔开，绝不覆盖。两个网页绑定同一篇文章时也一样。
- 并入后文章总批超过 64 KiB：绑定整体失败，返回 400，什么都不改。
- 改绑时已并入的总批留在原来的文章，与标注一致。

绑定之后，插件的卡片直接读写文章的总批，全局只有一份。总批没有定位失败的问题，重读原网页时也常有新想法，所以不沿用“绑定后只读”。

## 不变量

1. 一篇文章、一条 Path、一个未绑定网页至多一块总批；已绑定网页没有自己的总批。
2. 总批内容非空白；清空等于删除。
3. 删除文章、Path、对话或网页时，总批在同一事务中删除。
4. 版本不符的写入不改变任何内容。
5. 绑定时网页总批要么完整并入文章，要么绑定失败；并入不会改动文章原有的总批内容。
6. 总批不改变正文的折行，也不改变标注的坐标。
7. 总批的渲染遵守文档自己的图片规则，不让阅读页去加载外站内容。
8. 没有总批的 Palace 阅读页没有任何相关界面元素，只多一个 `n` 快捷键。

## 为什么不是这些替代方案

| 方案 | 不选的原因 |
| --- | --- |
| 放在标题下方 | 把正文往下推，每次打开都要先看过，读者已经否决 |
| 写在篇末 | 读完才看得到，写的时候要跳走或另做浮层；插件上还是浮动卡片，等于两套形态 |
| 挂在 Conversation 上 | 分支之间的想法常常相反，而且 Path 才是读者读的那一支 |
| 用没有引文的标注表示 | 标注的锚点是必填的，放宽它会动摇所有依赖锚点的绘制和迁移逻辑 |
| 插件用浏览器侧边栏 | 不与网页重叠，但会收窄网页，也与 Palace 上的形态不同 |
| 后写入者为准，不带版本 | 会静默丢掉一整段文字，见 D4 |

## 风险

- **批注被遮挡**：批注很密时，折叠行会盖住经过底部的卡片，只影响它们滚过的那一刻。
- **展开时盖住批注**：展开的卡片会盖住批注栏下半段，只在书写和阅读总批时发生。
- **本机草稿**：`chrome.storage.local` 里的文字只在这台电脑上，换电脑看不到，直到保存成功。
- **快捷键冲突**：`chrome.commands` 的默认键可能被占用，这时需要读者在浏览器里手动设置。
